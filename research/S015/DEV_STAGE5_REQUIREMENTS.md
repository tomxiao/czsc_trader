# 阶段五平台需求：行为等价与PTE运行检验

提出方：RSCH；修订日期：2026-10-22。本版依据用户对两个技术目的的确认及重新定义要求，替代提交`708f1549`中的需求提案。

状态：DEV已按[公共契约](../../docs/superpowers/specs/2026-10-22-stage5-public-contracts.md)在`codex/stage5-technical-validation`完成实现及[聚焦验证](../../docs/superpowers/plans/2026-10-22-stage5-technical-validation.md)；本文件保留RSCH需求边界。本次仅使用隔离合成测试，不执行S015研究检验、冻结或正式PTE部署，不改写既有研究证据。

## 1. 阶段五的定义

阶段五承接用户已经选定的策略，完成技术交付，并在用户精确批准后执行冻结。技术检验只有两个目的：

1. **行为等价：**StrategyCandidate与对应StrategyVersion的可执行实现，在相同输入和执行条件下行为一致。
2. **PTE可部署、可运行：**该版本的发布包能通过加载与认证，在指定PTE环境中正确完成策略运行和账户处理。

阶段五不承担研究审计。研究方法、候选比较、经济目标达标判断和选型理由属于前序研究工作；全部历史档案的完整性审计也不是阶段五前置条件。本需求不新增独立研究审计功能。

RSCH对交接材料、场景充分性与研究授权负责；平台校验技术输入并执行确定性检查。选型与冻结批准分别记录，平台不从研究报告推断授权。

## 2. 受检对象

| 对象 | 在阶段五中的作用 |
| --- | --- |
| StrategyCandidate | 已选定、内容确定的候选实现 |
| StrategyVersion | 拟冻结或已冻结的版本记录，包含版本身份和策略载荷 |
| 版本发布包 | `strategies/<strategy_id>/releases/<version>/`对应的源码、运行绑定与发布清单；这是实际交付和部署的文件集合 |
| StrategyRelease | 从版本记录构造的运行时表示，供SRT执行发布包中的实现 |

实现等价以运行行为为验收依据，不能只比较元数据或源码文本。双方身份本来不同，须分别核对各自预期身份，再比较行为。

冻结前构造完整的待冻结版本和发布包，但不登记为正式冻结版本。检验使用最终格式和确定的内容身份；获批后交付同一受检内容。版本哈希、包哈希和计划哈希分别记录，不混用。

## 3. 交接输入与最小校验

RSCH交付一组明确材料；这是业务输入清单，不要求DEV另建交接平台或存储系统。

| 必需输入 | 平台核对内容 |
| --- | --- |
| 具体候选及用户选型记录 | 候选标识、内容身份与用户选择的对象一致 |
| 候选源码、参数、依赖和执行合同 | 材料齐全、内容一致、可加载，合同受支持 |
| 拟定版本及冻结计划 | 版本身份明确，计划指向同一候选内容 |
| 获准的数据和输入绑定 | 内容身份、日历、预热、可用时间与声明范围一致 |
| 初始账户、费用和交易规则 | 比较双方使用同一条件 |
| 测试协议 | 明确场景、比较项、容差、PTE环境及资源范围 |

阶段五直接使用上述材料，不要求提供完整研究档案，不以读取或验证阶段一至四的交付报告作为技术检验前置条件，不检查候选是否属于某个排名或研究评审面板。研究报告链接可以作为背景保留，不触发递归读取。

RSCH可以提供原回测结果作为额外比较基准；此时只核对该结果的内容、输入及执行条件，并复现声明的结果。**原回测复现不是强制第三目标；必需的是当前候选与待冻结实现的直接比较。** 缺少原回测不妨碍在交接输入齐全时完成直接比较，报告须说明实际比较对象。

使用中的源码、数据、基准或包被改动必须发现；未参与检验的其他候选或历史材料缺失，不应阻断本次技术检验。技术检验也不对这些未使用材料出具完整性结论。

## 4. 目的A：行为等价

候选与待冻结实现分别经正常SRT入口，在相同数据、时间窗口、预热、初始账户、费用及交易规则下运行。发布实现只能使用包内源码及明确声明的环境依赖，不能借用实验目录中的候选代码。

比较策略合同涉及的信号、决策、目标仓位或份额、订单方向/数量/价格规则，以及相同历史执行条件下的成交、费用、现金、持仓和净值。影响后续决策的状态，通过公开执行事实、持久化事实和后续行为检验，不要求读取任意策略的全部内部变量。

离散行为精确一致；浮点比较使用事前声明的容差，默认零容差，不因失败而自动放宽。运行ID等非行为字段的排除规则须明确，不能排除影响决策或经济结果的字段。

输出双方身份、场景覆盖、比较规则、各项结果及首个差异的时点、字段和双方值。所有必需场景完成且符合协议，才可判定A通过。输入不足或执行中断不能计为通过。结论限定于声明场景，不表述为对所有未来输入的数学证明。

## 5. 目的B：PTE可部署、可运行

使用明确版本的PTE，在仓库`.tmp/`中的隔离注册表、数据空间和账户数据库运行。使用真实发布包及PTE加载、账户准备、决策、订单处理和持久化代码；时钟、外部数据来源和券商回报可由受控测试替身提供。

包、版本、依赖、运行绑定及部署身份必须正常认证，不能跳过认证后声称可部署。测试运行许可须与用户正式模拟交易批准区分；测试凭据不能被正常部署入口直接接受，不得伪造用户已授予PAPER_READY资格。具体隔离机制由DEV设计，不要求新建通用权限系统。

检验不连接真实券商、不操作生产根或已有账户。正式证据通过公共接口保留，临时环境不是最终交付。

| 场景 | 验收事实 |
| --- | --- |
| 部署材料加载及账户准备 | 包完整、身份一致、合同受支持，数据准备及初始化成功 |
| 入场、持有和退出 | PTE生成符合策略合同的决策和订单，并按受控成交回报正确更新账户 |
| 未成交或部分成交 | 实际持仓与意图区分正确，后续行为符合策略声明 |
| 重复请求或回报 | 不重复下单、不重复计入成交 |
| 持仓或未完成订单下恢复 | 重建运行组件后，从持久化绑定和账户事实恢复，后续行为符合合同 |
| 相关失败路径 | 包损坏、输入不完整/时间不合法、订单结果未知等明确失败或待对账，阻止不应产生的新单 |

RSCH按策略合同明确必需场景；多档位策略需覆盖其加减仓和目标变更行为。平台支持确定性驱动，不必等待自然交易日。候选所需场景未覆盖时B不能通过；不适用项须说明依据，不能静默跳过。

通用平台故障全集由DEV在平台变更时验证，不要求每次候选检验重复仓库级回归。PTE渠道回报与历史成交模型分别按各自合同验证，不要求不同成交事实产生相同账本。

B通过只证明该包在声明环境、场景下具备部署及运行能力，不证明实际生产已经部署、真实券商连通、长期收益或真实流动性。生产环境版本不同，需要另行确认兼容范围。

## 6. 检验、批准与冻结

业务流程为：明确交接输入 → 构造待冻结包 → 执行A和B → 交付报告及精确计划 → 用户批准 → 冻结同一受检内容。

冻结时核对最终版本和包与检验身份一致，按现有事务规则提交并返回真实回执；不能以未受检的新内容替换。审批及事务记录与受检发布内容分开，不因审批时间不同重新构造不同的策略实现。内容改变时相关技术结论失效，需重新检验。

冻结批准继续绑定候选、内容、报告、计划及版本。用户批准对象校验是交付流程要求，不构成研究审计。冻结及其记录发布不得再次递归验证整段研究历史。

正式模拟交易资格、SRT部署、创建PTE账户和生产启用分别按授权执行，不由阶段五PASS自动触发。

## 7. 输出与运行效率

平台分别返回A和B的结果，至少区分通过、失败、未执行和执行未完成。两项目的所需检查均通过才能给出整体技术PASS。正式证据发布、冻结、部署及PTE启用状态分别记录。

报告保存受检身份、环境、输入引用、场景、比较规则、检查结果、差异、范围限制与实际耗时。新报告及其直接支持证据须完整可核验；不因为它们关联选型或历史报告而展开全研究链。发布失败须保留计算事实并明确正式交付未完成。

工作量应主要由本次输入、受检包和测试场景决定。选型记录、检验、报告发布及冻结过程中均不得隐式引入研究审计。记录主要步骤与总耗时；长步骤定期报告进度，支持预算和中断，未完成不得返回PASS。

本需求不指定缓存系统或并行架构，也不把跨调用缓存作为交付条件。DEV应先消除无关读取和重复处理，再基于同工作量测量耗时、内存及是否仍需优化。

## 8. DEV验收要点

1. 候选与发布实现一致时A通过；改变信号、订单或影响后续决策的状态能定位差异。
2. 必需输入、受检内容被篡改或执行条件不一致时明确失败。
3. 真实PTE业务链路完成第5节必需场景，失败、未知和中断不被汇总为成功。
4. 测试环境隔离，普通部署入口拒绝测试凭据；最终冻结内容与受检内容一致。
5. 只提供第3节的明确交接材料，不挂载完整阶段一至四档案，仍可执行检验和发布；材料中必需技术依赖须齐全。
6. 添加、移除或损坏无关候选及历史材料，不改变本次技术结果，不增加无关账户的读取/解码和回放；本次使用的材料损坏必须失败。
7. 现有研究概览能够识别合法检验证据，不把辅助记录计为研究账户；未知或损坏记录明确报告。概览失败与A/B结论分别呈现，不能因概览失败伪造或撤销已发生的技术事实。
8. 原交付保持不可变，新口径使用新的检验报告；不自动迁移历史PASS，不修改既有冻结策略。

概览布局兼容是现有平台缺陷的配套修复，不构成第三个技术检验目的。DEV提供最小接口方案、聚焦验证和完整调用链的实际性能数据；不要求为本需求扩建研究审计能力或重新执行经济评价。
