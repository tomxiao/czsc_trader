# 研究治理空间使用规范

本文规定`research/`的内容归属、组织、写入和引用边界。
研究员的权限、研究方法与阶段责任由研究员Agent文档维护；平台接口由各模块使用说明维护。
实验空间遵循[实验空间使用规范](../experiments/README.md)。本文不复制上述内容。

## 空间职责

`research/`承载跨实验的批次治理，保存研究意图、用户确认的目标与约束、阶段一任务合同、
真实授权与治理决定、登记索引和交接导航。批次当前状态由治理记录及HANDOFF呈现。

| 内容 | 位置及规则 |
| --- | --- |
| 批次交接导航 | `<策略ID>/HANDOFF.md`；记录当前状态、精确产物引用和待决定事项 |
| 阶段一任务合同 | `<策略ID>/mandates/<修订>/`；通过统一交付API发布，已发布修订保留 |
| 批次治理依据 | `<策略ID>/materials/`；仅存跨实验目标、约束、授权、注册与意图变更依据 |
| 用户决定 | `<策略ID>/decisions/`及其`objects/`；通过公共API记录真实用户决定 |
| 批次与候选登记 | `registrations/<策略ID>/`；通过公共API维护，候选实体归属来源实验 |
| 冻结事务治理 | `<策略ID>/freeze_requests/`；通过公共冻结API生成和查询 |

每份材料明确用途、来源、适用批次与版本。授权文件必须忠实记录真实用户指令；自行保存文件
不能产生授权。变更按后继记录承接，不能覆盖已被正式合同或交付绑定的原件。

## 实验内容的归属

实验专属的问题、协议、代码、数据诊断、来源探查、执行记录、失败证据、交付和验证结果，
保存到对应实验空间。不能以便于汇总为由集中输出到批次`materials/`。
一次性脚本、调试输出和未作为正式证据的中间文件放入`.tmp/`。

治理API请求及返回结果按作用范围保存：跨实验的批次注册、意图变更属于本空间；
某个实验或交付的核验结果属于该实验。重复保存正式结果时注明权威产物和副本用途。

## 引用方向与交接

本空间可以通过精确身份、版本和哈希引用实验成果，不复制维护另一套实验结论。
实验不得反向引用本空间及其内部文件，具体约束和固定快照要求见实验空间规范。

进入实验前，由研究编排核对当前真实授权和确认合同，向实验提供当时有效的固定快照。
固定快照保留完整内容、版本、原始内容哈希和来源身份，不能通过编辑副本改变目标或授权。
治理区后续变化通过新授权及后继实验承接，不改变已封存实验的依据。

## 维护与历史记录

平台治理文件通过公共API更新；研究员可在获准范围内编写治理材料和HANDOFF。
文档采用相对路径。目录规则调整前先核对已发布合同、交付和封存档案的引用。
历史原件保持可追溯，迁移、删除和引用修订属于单独的维护任务；规则更新不自动授权迁移。

## 配套数据空间

研究独立取数使用相对仓库根目录的DFLS空间，默认`data/research/<策略ID>/`，由宿主显式指定。
同一获授权任务的实验可复用该空间；需要隔离时显式选择任务子目录。
TDR账户评价与策略回测使用平台管理的`data/backtest/`空间。
数据空间属于DFLS管理的资产存储，研究员通过公共API准备与读取，不人工修改内部文件。
正式复算引用需要的资产必须保留；输入清单或实验副本不能自动替代原空间。
初始化与接口说明见[REX使用说明](../packages/research_experiment/README.md)。
