# 研究目录说明

`research/` 按研究批次保存任务材料、实验实现、数据与结果、阶段交付、用户决定及交接信息。
本文说明资料位置、保存与修改规则，并提供批次入口。

## 批次空间与落盘职责

新研究及 S013 使用以下布局；其他历史批次的实际资料位置以其 `HANDOFF.md` 及关联引用为准。

```text
research/<批次>/
  batch.json                         # 批次身份
  HANDOFF.md                         # 当前状态、成果引用及下一步
  batches/                           # 后续立项凭据对应的材料
  materials/                         # 批次级任务、授权依据、总体约定及跨实验决定

  experiments/<实验>/
    experiment.json                  # 实验身份
    report.md                        # 每个实验的报告入口，独立于阶段交付
    report_ref.json                  # 报告发布后指向不可变快照；创建时不存在
    src/                             # 验证程序、策略实现、自定义组件
    protocols/                       # 假设、方法、参数域、搜索及自检方案
    notes.md                         # 观察、判断变化、修正及停止依据
    others/                          # 定义以外的资料，按研究需要组织

  deliveries/<阶段>/<修订>/
    report.md                        # 阶段报告
    receipt.json                     # 交付身份及关联文件引用

  decisions/                         # 正式用户决定
  freeze_requests/<请求ID>/           # 冻结请求及事务记录

  assets/
    data/                            # 实际使用的数据资产
    runs/<实验>/<运行>/               # 请求、结果、搜索数据库、检查点
    evidence/<实验>/                 # 显式发布的正式证据
    candidates/<候选>/               # 候选载荷、源码及依赖快照
    deliveries/<阶段>/<修订>/         # 完整机器交付包

research/registrations/               # 研究族、立项凭据和候选登记
```

## 保存与修改规则

任务材料、实验源码、方案、笔记及其他资料按研究需要编辑、补充和更新。运行结果、搜索数据库和检查点按接续需要保存和更新；支持结论的材料保存为正式证据。

单个实验的过程材料内聚于该实验目录，不新增到批次`materials/`。共享材料指定一个归属位置并显式引用。每个新实验必须有根报告，失败、取消及未完成同样说明实际结果；根报告不再依赖阶段交付，也不再要求复制阶段报告。独立报告发布及结构检查见[研究工具](../docs/RESEARCH_TOOLS.md)。历史目录及已发布原件不自动搬迁，旧实验缺少新入口应如实显示，不能据此改写原结论。

数据资产保存实际使用的版本及研究引用。正式证据、候选快照和历史研究原件按原始内容、身份及哈希保存；修正形成新证据或新候选，并关联原有成果。

阶段报告、回执和完整交付包按同一阶段及修订对应保存，修正形成新修订。身份、登记、用户决定及冻结记录保留其授权依据与状态历史。

`HANDOFF.md` 随研究进展更新，记录目标、阶段、授权、当前结论、精确成果引用、所需资产位置及下一步。接续材料包含所需的数据资产、正式成果及必要运行状态。
