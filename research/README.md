# 研究目录说明

`research/` 按研究批次保存任务材料、实验实现、数据与结果、阶段交付、用户决定及交接信息。
本文说明资料位置、保存与修改规则，并提供批次入口。

## 研究政策与平台需求

研究职责、阶段一目标及稳健性标准见[RSCH指南](RSCH_AGENT.md)，其中包含2026-10-21确认的完整区间收益、双频率及稳健性政策；工具入口及正式交付方式见[TDR目标绑定](../src/czsc_trader/README.md#完整目标集合的交付绑定)。新契约不改变历史批次资格或授权。

主指南维护共同研究方法和五阶段职责；[A股补充](guides/CN_RESEARCH.md)与[美股补充](guides/US_RESEARCH.md)
说明各市场的时序、交易条件与样本解释。市场补充不另设验收政策，研究员在阶段一结合已确认要求落实本批次约定。
平台能力按相应请求与证据类型核验；美股研究计算与正式候选、阶段交付的支持边界见
[TDR美股研究接口](../src/czsc_trader/README.md#us-equity-research)，不能直接套用下述既有交付类型。

阶段二的核心产物与评价对象是由有效组件构成的策略原型，组件验证是支撑证据；阶段三承接有依据的原型，完善结构并优化、检验达标能力。具体评价与推进要求见[RSCH五阶段目标与交接](RSCH_AGENT.md#4-五阶段目标与交接)。阶段二正式原型成果使用`PROTOTYPES`及`PrototypePanel`，关联实现身份、定义快照、组件职责、完整账户和必要对照；`COMPONENTS`及`ComponentPanel`继续保存组件支撑证据。公共发布、校验及概览入口见[TDR原型交付](../src/czsc_trader/README.md#策略原型交付)。

原型无需先登记为候选，研究员的建议发展、继续研究或停止判断不构成平台认证或阶段批准。缺少账户的原型应明确缺证原因，完整负面交付也可以没有原型；不要求每个探索想法预先登记。历史`COMPONENTS`、`CANDIDATES`交付不迁移、不改写、不自动转为原型，新原型交付可以显式引用既有正式证据，无须仅为交付类型变化重跑实验。

## 批次空间与落盘职责

新研究及 S013 使用以下布局；其他历史批次的实际资料位置以其 `HANDOFF.md` 及关联引用为准。

```text
research/<批次>/
  batch.json                         # 批次身份
  HANDOFF.md                         # 当前状态、成果引用及下一步
  batches/                           # 后续立项凭据对应的材料
  materials/                         # 批次级任务、授权依据、总体约定及跨实验决定

  experiments/<实验>/
    experiment.json                  # 实验身份
    report.md                        # 每个实验的报告入口，独立于阶段交付
    report_ref.json                  # 报告发布后指向不可变快照；创建时不存在
    src/                             # 验证程序、策略实现、自定义组件
    protocols/                       # 假设、方法、参数域、搜索及自检方案
    notes.md                         # 观察、判断变化、修正及停止依据
    others/                          # 定义以外的资料，按研究需要组织

  deliveries/<阶段>/<修订>/
    report.md                        # 阶段报告
    receipt.json                     # 交付身份及关联文件引用

  decisions/                         # 正式用户决定
  freeze_requests/<请求ID>/           # 冻结请求及事务记录

  assets/
    data/                            # 实际使用的数据资产
    runs/<实验>/<运行>/               # 请求、结果、搜索数据库、检查点
    evidence/<实验>/                 # 显式发布的正式证据
    candidates/<候选>/               # 候选载荷、源码及依赖快照
    deliveries/<阶段>/<修订>/         # 完整机器交付包

research/registrations/               # 研究族、立项凭据和候选登记
```

## 保存与修改规则

任务材料、实验源码、方案、笔记及其他资料按研究需要编辑、补充和更新。运行结果、搜索数据库和检查点按接续需要保存和更新；支持结论的材料保存为正式证据。

单个实验的过程材料内聚于该实验目录，不新增到批次`materials/`。共享材料指定一个归属位置并显式引用。每个新实验必须有根报告，失败、取消及未完成同样说明实际结果；根报告不再依赖阶段交付，也不再要求复制阶段报告。独立报告发布及结构检查见[TDR实验与证据发布](../src/czsc_trader/README.md#5-显式发布和读取证据)。历史目录及已发布原件不自动搬迁，旧实验缺少新入口应如实显示，不能据此改写原结论。

数据资产保存实际使用的版本及研究引用。正式证据、候选快照和历史研究原件按原始内容、身份及哈希保存；修正形成新证据或新候选，并关联原有成果。

阶段报告、回执和完整交付包按同一阶段及修订对应保存，修正形成新修订。身份、登记、用户决定及冻结记录保留其授权依据与状态历史。

原型交付公开入口为`deliveries/PROTOTYPES/<修订>/`，完整包位于`assets/deliveries/PROTOTYPES/<修订>/`。原型编号只在面板内识别原型；跨交付引用使用精确交付引用与原型编号组成的`PrototypeReference`，其来源交付须列入本次`DeliveryDefinition.predecessors`。修改实现或研究判断形成新修订，旧版本保持可定位；不同修订中的原型不自动累加为独立原型数量。

`HANDOFF.md` 随研究进展更新，记录目标、阶段、授权、当前结论、精确成果引用、所需资产位置及下一步。接续材料包含所需的数据资产、正式成果及必要运行状态。
