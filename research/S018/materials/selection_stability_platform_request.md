# 平台需求：阶段四选型稳定性自检

状态：RSCH提交DEV评审，尚未批准实施。日期：2026-11-05。

适用范围：后续各研究批次，覆盖A股与美股；S018为提出需求的批次和后续可选应用案例，不限定候选、标的、时间窗口或净卡玛目标。

本文件只定义研究需求及验收条件，不修改RSCH指南、平台接口、既有研究结论或正式交付，不授权补算、阶段推进、冻结及生产操作。

## 1. 用户决议与问题

用户认可新增“选型稳定性”自检，随后明确“前面五项不用动”。本次保留参数敏感性、时间稳定性、收益集中性、执行敏感性、统计不确定性五项的既有定义、结果及验收政策，只提供第六项能力。

新增项回答：使用同一套实际选型规则，在不同连续历史区间内选择方案后，所选方案在随后连续区间的达标情况、目标表现和相对排名是否稳定。

与原时间稳定性的区别：

- 时间稳定性：固定一个候选，观察它在不同时期的表现。
- 选型稳定性：固定选择规则，每个选择期重新筛选及排序，再观察当期选中方案的后续表现。

本项不估计研究选择偏差，不依赖试验次数或有效试验次数，不输出PBO、DSR或未来成功概率，不新增经济硬门，也不自动进入原阶段四候选排序。

## 3. 首版范围与责任

### 3.1 首版支持

1. 固定候选集合的回顾性选型稳定性诊断，使用已存在、同口径的标准条件连续账户及匹配买持。
2. A股、美股，至少覆盖平台已支持的日线及日内账户；切窗按实际交易日，不把K线根数当交易日。
3. 单目标净年化收益或净卡玛，方向及必要的顺序次级指标显式声明；保留实际精度和并列规则。
4. 标准条件下的绝对/相对收益风险门、条件基准门、滚动交易频率门，沿用现有已支持语义。
5. 批量窗口计算、逐窗结果、候选汇总及独立证据发布，历史材料不自动迁移。

复杂帕累托/部分排序、依赖参数邻域或压力账户的选择、无法形式化的人工选择，若首版不能忠实支持，应明确返回“不支持该选择规则”，由RSCH另行提出适配需求。禁止删项后冒充原规则。上述首版范围不是重写其他批次的选型政策。

### 3.2 不纳入本次

- 新增选择偏差自检；改造、删除或重算前五项及现有PBO/DSR链路。
- 在窗口内重新搜索参数、训练模型、调整结构或调节窗口以改善结果。
- 独立样本认证、前瞻交易、从选择时点重新投入资金的账户回放。
- 将多个赢家账户拼成动态换仓策略或组合净值。
- 新增收益、回撤或频率的统一验收阈值、综合稳定性分数。
- 改写S018既有交付状态或自动开展C9380补查。

### 3.3 职责

RSCH提供研究族范围、可比性分组、原选择规则、窗口、结论边界和计算预算；DEV提供明确的类型、计算、状态、资源统计和证据保存能力。平台不推断研究目标，不签发“经济上可靠”“独立验证通过”等判断。

## 4. 最小输入契约

以下为业务信息要求，类型及接口名称由DEV评审，不要求新增同名接口或采用任意字典、表达式字符串、回调函数。

| 输入 | 必需信息 |
| --- | --- |
| 研究范围 | 批次、诊断对象、固定候选清单、可比群组、回顾性研究模式、资料覆盖与限制 |
| 候选来源 | 精确候选身份/内容哈希、账户来源引用、数据及执行语义、成本、基准、币种、市场与日历、回撤口径 |
| 选择规则 | 所模拟的实际决策环节及规则版本、目标指标、硬条件、排序顺序、精度及并列处理；规则来源引用 |
| 观察规则 | 后段逐项核对的条件及目标、同窗基准；默认与所模拟选择规则对应，任何差异须显式声明 |
| 窗口方案 | 明确的选择期/观察期成对日期，或可确定展开为该清单的交易日长度、步长与起点；尾部及重叠约定 |
| 资源约定 | 候选数、窗口数、预期候选-窗口计算量、并行/内存限制、预算上限及超预算处理 |

候选集包含真实参与该环节选择的失败者，不能从全样本达标者倒推出选择期可选集。重复的完全相同定义可由RSCH显式合并并保留来源映射；收益相同的不同策略身份不自动合并。

输入中的“选择规则”不是自动引用全部阶段四验收条件。例如阶段三曾按经济与频率硬门筛选、按净卡玛择优，本项就检验这套规则，不自动增加后来才开展的参数和费用压力检查。若实际选择依赖未提供的条件，应报告不完整或不支持。

## 5. 窗口和账户语义

### 5.1 时间边界

- 每对窗口均须满足选择期末早于观察期初；默认紧接下一个实际交易日，其他间隔须显式给定。
- 只使用完整的预定窗口，不补任意尾窗、不缺日补零、不自动缩短窗口；逐对输出实际覆盖交易日。
- 观察期数据不得影响当轮候选筛选、选择期指标、并列处理或选中名单。观察期缺失只能影响后续观察状态，不能反向排除选择期赢家。
- 选择期筛选不能使用全样本达标标签；预热仅提供当时可得的历史，不计入窗口绩效。
- 候选全集利用完整开发池形成时，始终标记回顾性；即使逐窗计算未读取未来数据，也不能宣称候选构建过程未使用未来信息。

### 5.2 账户切片

首版只分析已有连续账户：继承真实现金、持仓与交易，不假设窗口开始重新投入本金。

- 窗口收益以开始日前一交易日的实际净值为基点；原账户首日使用原初始权益。基准采用相同边界。
- 年化沿用已声明的市场/账户口径，按真实交易日数计算；同时输出区间收益和年化值。
- 局部最大回撤从窗口基点开始，使用声明的采样粒度。BAR_CLOSE不得降为日末回撤；有必要时明确其与全账户历史高点回撤的差别。
- 净卡玛沿用既有指标有效性约定。零/近零回撤、非有限值等不能替换成任意大数，不能因此获得第一名。
- 闭合交易按真实退出日归属，窗口前入场、窗口内退出照原定义计入。滚动60日等频率只使用完全落入相应分析窗口的完整交易日子窗；原闭合口径不变。
- 来源缺少目标所需的逐柱净值、交易周期或基准时，报告不足；不得由仅有日收益矩阵推造BAR_CLOSE回撤或交易频率。

## 6. 选择、观察与并列

每个窗口执行以下确定性过程：

1. 在完整声明候选范围内，计算选择期所需指标并逐项核对条件，保留每个排除原因。
2. 对证据齐备且通过条件者按原规则排序。全体明确不达标时输出“未选出”；只剩一个可选者可正常选出，但不提供虚假竞争证据。
3. 精度相同档位且全部排序项相同时，保留并列最优集合，默认不按候选ID挑经济赢家；ID只稳定展示顺序。调用方已有明确决胜规则时，按其支持范围执行并留证。
4. 锁定当轮选中名单，再取得后段观察事实；逐个保留其条件状态、目标值及同窗基准差。
5. 后段相对排名的参照集合固定为当轮选择期的可选集合，不能按后段是否达标再次筛掉不利成员。目标排序和硬门保持结果分开报告，未达标者的原始目标排名不冒称完整选择资格排名。

若声明选择期候选缺失且可能改变谁入选，首版整轮选择记“证据不足”，不得默默在剩余子集挑赢家；部分事实可展示。若能由现有事实确定已违反硬门，可明确排除而不要求无关指标。

若后段参照集合存在缺失，保留已取得的选中候选绩效，但完整相对排名记不可计算，分母仍展示原集合规模。并列结果逐个列示，不随意平均净值或当成一个组合。若最终人工选择无法由规则复现，输出并列/推荐集合，不声称复现了人的决定。

## 7. 输出及状态

### 7.1 逐窗输出

- 窗口身份与选择/观察日期、实际交易日数、来源及协议引用。
- 声明候选数、证据齐备数、达标数、排除清单及原因。
- 候选选择期指标、条件判断、排序依据及并列最优集合。
- 选中成员后段指标、逐项条件保持情况、同窗基准差、相对排名区间与参照集合规模。
- 数据不足、不可比、不支持、未选出等明确原因；不把这些状态填为零绩效。

### 7.2 汇总输出

1. 计划窗口数、完成数、无候选达标数、选择证据不足数、后段观察/排名不足数。
2. 每个候选进入最优集合的次数和分母；多人并列时各自计一次，不强求频率合计为100%。
3. 后段达标保持的明确计数：以“窗口-选中成员”为单位，分别列出通过、失败、无法判断；展示通过/可判断数以及可判断/全部选中观察数，不隐去未知分母。
4. 后段目标分布、同窗基准差、选择期与后段目标差，标注窗口长度；长度不同的卡玛差只是描述，不解释为纯粹过拟合损失。
5. 后段排名变化、最差区间及其来源；少于两个可比较成员时排名诊断不适用。
6. 重叠窗口、并列成员相关性、已见开发池及资料覆盖限制；不生成基于独立试验假设的置信结论。

候选入选次数不等于DSR的试验次数，不生成“有效试验次数”。不因身份频繁切换自动认定经济表现不稳定；行为相似性解释由RSCH结合既有证据完成，首版不增加聚类计算。

### 7.3 状态分层

区分计算是否完成、资料是否齐备、选择是否产生以及后段条件是否通过。合法输入可能得出无人达标或不利表现，属于有效研究结果；非法时间边界或类型应尽早拒绝。方法不支持和资料不足不能标为自检完成或通过。

## 8. 接口边界、效率与留证

希望业务上形成“从已有账户取得所需窗口事实”和“依声明规则完成选择/观察分析”两类明确能力；可批量组织，接口数量及模块划分由DEV决定。

- 优先复用SE指标和目标判定，避免维护第二套收益、回撤、频率公式。选择规则不能被固定的阶段四完整排序合同绑死。
- 同一来源账户一次读取/投影后供全部窗口复用；同条件基准复用。不能按候选×窗口重复展开全部账户或重复准备行情。
- M个候选、K对窗口，计划约2MK个候选窗口事实（相同窗口可复用），不代表2MK次策略回放。输出实际来源读取、窗口计算、比较和发布的分段工作量与耗时。
- 资料足够时新增策略回放、候选注册、数据下载、PBO/DSR及前五项自检重算均为0；不能因缺失自动回放、扩大候选集或降低指标粒度。
- 类型及时间边界等输入检查与计算所需的一致性检查明确执行；不附带历史账户认证、源策略复验或隐式数值重算。
- TDR只按显式请求读取、组织和发布；发布/INTEGRITY冷读保存并核对声明结果，不重新运行选型计算或账户认证。
- 请求、规则来源、窗口清单、结果、资源统计及研究限制可作为独立类型证据附入阶段四。优先独立附证接入，是否需要新增交付字段/版本由DEV评估；不强迫前五项重新生成、不覆写旧协议和结果。

## 9. 聚焦验收场景

| 场景 | 预期 |
| --- | --- |
| 净收益与净卡玛选出不同方案 | 严格跟随声明目标；没有隐式夏普计算 |
| 原目标最高者违反选择期硬门 | 排除理由可见，按原规则选择其他达标者 |
| 后段收益或完整性变化 | 前段指标及选中名单保持不变；只改变后段结果或状态 |
| 全样本达标但选择期不达标 | 不得依全样本资格入选 |
| 全体不达标、仅一人达标、多人并列 | 三种状态分别正确；不强选、不制造竞争、不以ID打破经济并列 |
| 前段候选证据缺失、后段参照证据缺失 | 前者不输出完整赢家结论；后者不改变赢家，只限制观察排名 |
| 标准收益/卡玛、回撤及双频率边界 | 与现有公式和严格/包含边界一致；窗口不足不放宽要求 |
| 跨窗口持仓、窗口首日、零回撤及BAR_CLOSE | 继承账户和采样口径正确；无伪造平仓或无穷高分 |
| 非连续日历、半日市、A股/美股日线与日内 | 按各市场真实交易日切窗，交易含义不串用，不引入网络依赖 |
| 后段不达标者仍有目标排名 | 保持状态与目标排名分开，不因未来失败缩小参照集合 |
| 数据/成本/基准/执行上下文不同 | 不自动合并，返回明确不支持或不可比原因 |
| 不支持的完整阶段四排序或人工决胜 | 明确不支持，不删掉条件、不补造其他自检事实 |
| 批量计算与独立小样例 | 指标、集合、排名与计数一致；读取复用可观察 |
| 发布及冷读 | 输入输出引用保留，账户回放、前五项及本项分析重算计数均为0 |
| 历史交付 | 原读取和前五项行为不变，不批量迁移、不改变研究资格 |

使用双市场合成小账户完成聚焦验收，材料写入项目.tmp；不以修改或重算真实S018作为工程测试前提。
