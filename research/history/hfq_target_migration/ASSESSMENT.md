本轮已完成指南修订和只读迁移盘点。未修改冻结包、候选、安装记录或账户，未运行研究回放，未访问生产。本文是迁移工作评估，不是升级批准或等价性通过报告。

## 结论与范围

本地有8个登记且有安装记录的冻结版本，均声明主行情 `analysis_price=RAW`、缺少当前必填的 `execution_policy`，且实现仍输出订单或订单腿，不能直接在新版契约下运行。主行情声明为RAW不代表原金融信号都用RAW：大多数已有HFQ辅助输入，必须逐项区分其观察与执行用途。

盘点依据为 [策略注册表](../../../strategies/registry.json)、各版本记录及 [本地安装记录](../../../strategies/deployments/)。本地8版包括7个A股版本和1个美股版本；这不是prod活动账户数量，也不据此重新解释此前“七个账户”的验收范围。

2026-11-08按后续用户讨论修订：统一目标仓位以当前策略账户权益为分母，分阶段入场的判断及比例归策略，资金和订单归EC。当前EC已有按目标权益比例规划的能力；S018需要改写目标表达并评估原固定现金预算被替换后的差异，不应归结为平台不支持S018，也不要求渠道识别其交易阶段。

下表7个A股版本的原执行政策映射仅是保留旧规则的技术盘点，不代表已符合统一仓位语义。涉及锁现金、锁数量或事件指令的版本仍须逐项评估仓位定义差异，不能据现有 `FROZEN_RULE` 或 `INTRADAY_OVERLAY` 可调用就宣告迁移完成。本次具体修订S018方案，不修改其他冻结版本。

## 统一仓位定义与S018适配方案

### 比例基准及职责

设目标仓位为 `w`，EC规划时的策略账户权益为 `E`，目标持仓市值为 `w × E`。当前实现按确认现金、应收款及以执行参考价计量的持仓市值计算E；应收款计入权益不等于可用于买入，可用现金仍独立约束订单。模拟盘使用该策略虚拟账户权益，不使用渠道总资金作为每个策略的分母。历史渠道按HFQ模拟价格计量，模拟交易按RAW价格和确认账户计量，策略均只给出无量纲比例。

策略决定何时改变w；EC按每次采纳的目标、确认账户、费用、数量步长、可卖量及可用现金形成订单。目标未变也可能再平衡，目标不保证成交后精确达到。EC不判断试探、修复、最早加仓日或S018的分组条件，不从解释字段读取命令。

当前 [EC规划入口](../../../packages/execution_channels/src/execution_channels/planning/__init__.py) 已有 `TARGET_POSITION` 的 `target_equity_fraction` 模式；可作为本方案的执行入口，尚未通过真实S018端到端适配验收。不新增S018专用执行政策。

### S018目标函数与状态

沿用冻结参数：按原入场分组取得最终目标比例 `a ∈ {1.0, 0.375}`，初始比例系数 `f=0.5`。a在一次入场周期内固定，不因持仓后的分组重算而改变。

| 策略情形 | 目标w | 状态处理 |
| --- | --- | --- |
| 空仓且无入场信号 | 0 | 无持仓周期 |
| 满足入场信号 | `f × a`，即50%或18.75% | 提出初始目标；无真实成交不得据此假定已持仓 |
| 已持仓、尚未确认提高目标 | 维持 `f × a` | 保留入场锚点、周期分组比例及持有时钟 |
| 满足原最早加仓日与MU、SOXX修复条件 | a，即100%或37.5% | 策略将“目标已提升”状态置为真；未成交不冒称实际加仓完成 |
| 目标已提升且尚未退出 | 维持a | 不因修复条件后来消失自动降回试探比例 |
| 满足退出条件 | 0 | 退出优先；仍有持仓则持续输出0，确认清仓后结束周期 |

入场锚点、分组比例、持有时钟及目标提升状态属于金融决策状态。首次真实入场及持仓结束依赖已确认反馈；未成交重试、部分成交和重启时必须正确保存相关状态。持有天数仍按原首笔实际入场区间起算。保留原最早加仓日、MU/SOXX修复阈值、最长持有及复核退出条件，不把这些条件下放EC。

移除策略 `entry_budget`、现金计算、报价取整、股数与订单输出；以比例状态替代资金状态。旧 `active.buy_fills==1` 不再承担“尚未加仓”的判断：统一比例执行可能在试探期发生再平衡成交，成交笔数无法代表金融阶段。新方案用显式“目标已提升”状态决定是否已发出提升目标；实际持仓仍以确认成交为准。这是明确的状态语义变化，需在对照中披露。

### 相对原冻结实现的行为差异

[原策略](../../../strategies/S018/releases/v1/src/strategy_runtime/strategy.py)以入场可用现金乘分组比例锁定预算，首单花其50%，确认后按原预算减已买成本补仓。新方案目标按当前权益计量：价格变化、费用和账户事实变化都会影响目标金额；即便w未变，也可能买入或卖出以靠近目标。原实现未确认加仓时通常不下买单，已加仓后也不持续再平衡，因此两者不能宣称订单或绩效等价。

分组参数原为现金分配比例，新方案将其解释为最终目标权益比例；保留数值不等于保留经济含义。已确认的1%买入溢价、0.1%单边模型费率及原金融触发阈值保持，费用和取整仍由EC计算。平台因最低单位等约束阻断时，策略不把目标改为0来伪装无入场机会。

这是受控的目标表达与执行语义调整方案，不是纯接口搬迁。旧C9380与旧冻结包的评价证据保留；新实现需要新候选身份和差异结果，不能继承原绩效或自检通过结论。本轮仅修订方案，未批准具体新冻结内容或生产生效。

## 数据、身份及状态迁移

- 数据继续经DFLS取得。分别保留供应商、获取方法、可用时点及内容身份。HFQ主行情、辅助行情和历史执行行情使用一致价格尺度；对应价格限制也须一致。来源或获取方法改变时，先比较数据，再比较信号，避免把数据变化误归为策略修改。
- A股ETF和Futu的实际权限、覆盖及完整性需在迁移验证时确认，本轮没有进行在线供应商请求。DFLS直供和自行计算可能有不同成交量含义，特别影响S001、S007及容量约束；HFQ标签也不自动保证总收益或历史时点可得性。
- 新实现通过研究候选和正式原地升级入口更新发布身份，保留旧源码、历史选型及证据。平台接口见 [TDR冻结运行升级](../../../src/czsc_trader/README.md)，不直接改写版本、冻结包、注册或安装记录。
- PTE正式输入须采用当前 `FormalV4Inputs` schema 3，独立绑定RAW执行参考价；SRT只绑定HFQ观察。此schema与冻结包 `runtime_binding.json` 的schema 2属于不同文档，不可混用。
- S001/S002/S007/S011/S015的 `locked_quantity`、`had_position`，S003的 `core_quantity` 中承担执行职责的状态迁入EC。旧负值哨兵不得直接写入新锁字段，应依据旧状态和已确认账户事实显式映射；含预算或分阶段状态的账户另核对成本、锁和未完成订单。
- PTE已有显式状态映射入口，见 [账户维护实现](../../../packages/paper_trading_engine/src/paper_trading_engine/v4_account_maintenance.py)。源码升级、输入重建、账户状态映射、生产重绑及生效分别留证；本次未读取生产状态，不能提前断言每个在途账户可以直接续接。

## 验证设计与迁移顺序

| 验证层次 | 比较条件与结果要求 |
| --- | --- |
| 金融信号与状态 | 固定同一可得HFQ输入，逐时点比较原金融规则与新目标表达，覆盖前缀、入场、持有、退出和阈值边界；目标表示发生变化时比较经济含义，记录明确映射，不机械比较原0/1与新分配比例 |
| 模拟执行规则 | 对同一RAW参考价、确认账户与费用，将旧公式作为隔离对照，逐项比较EC生成的报价、数量、订单依赖及状态；保持原合同的版本核对等价，S018按已列明的新比例语义解释差异。覆盖资金不足、部分成交、未成交、退出和重启；旧代码不接回正式运行链路 |
| 新历史账户 | 在HFQ价格和整数模拟单位下验证策略与买持使用一致合同、账本连续及阻断语义；保留新结果，不要求与旧RAW回放净值相等，不将新结果直接称为原绩效等价 |
| 技术交付与状态映射 | 新候选与冻结包同模型行为等价；隔离PTE使用HFQ观察、独立RAW执行输入，验证状态映射、重绑和恢复。生产授权与模拟交易资格另行处理 |

优先以S018验证“策略目标比例—EC通用规划”的完整链路，不以增加渠道金融逻辑为前提。其余版本先逐项明确旧锁定规则与统一比例语义的差异，再确定适配顺序；原先按旧执行政策搬迁的顺序不作为已批准实施安排。

S018聚焦验证分三层：固定相同HFQ观察及确认反馈，核对分组、入场、提升目标和退出；固定相同执行价格与账户，比较旧资金算法和新目标算法，单独量化再平衡及成交笔数状态的影响；最后分别检查HFQ历史账户与RAW隔离模拟链路。若旧实现无法在新版SRT运行，使用隔离的原公式对照，不恢复旧正式入口。两个渠道采用同一目标函数，但不要求账户数值相等。

工作容量为8版源码/定义迁移及逐版技术验证，S001两版可复用共享实现对照，但保留各自配置结果。仅做与变更相关的聚焦验证，不在本轮启动参数搜索、全仓回归或重跑全部阶段四。正式回放窗口、所需账户数与预计耗时在实施前按已有资产及用户批准范围确定；本评估不虚报计算预算或已通过数量。
