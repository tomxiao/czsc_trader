# S014 甲醇上游可用性核查

日期：2026-10-18。结论：**当前账户有权限，主力日线和映射在研究交易日上覆盖完整；原始月份合约只核查了部分，历史时点可用性仍有证据缺口。不能直接把主力连续涨跌当成已准备好的商品信号。** 本轮核查目标已完成，尚未获得收益有效性结论。

## 授权与实际使用

用户批准最多8次Tushare实际调用，失败计数，仅核查甲醇权限、历史覆盖和时点。本轮实际8次、成功8次、失败0次、余额0；没有自动重试、分页追加或跳转。使用仓库当前配置的同一账户，经现有客户端逐次守卫HTTP请求；不展示凭据。公开说明网页阅读不计入数据API调用。

这些返回值保留为上游核查证据，未伪装成DFLS正式准备资产。未创建新的研究实验、收益模型、策略账户或候选，未修改平台、费用、执行、年度目标，也没有恢复公告追溯。历史66候选、全部目标通过0个及十轮账户额度耗尽状态不变。

## 2. 数据语义：换月确实能造成假方向

最后一次换月发生在2026-09-28，前一交易日为9月24日：

| 价格 | 数值 |
| --- | ---: |
| 前任主力MA2610在9月24日收盘 | 3513 |
| 新主力MA2611在9月24日收盘 | 3191 |
| 新主力MA2611在9月28日收盘 | 3249 |

连续主力直接把3513接到3249，显示下跌；同一新合约实际从3191变到3249，是上涨。两合约在前一日相差322个报价单位，说明直接对连续收盘价计算涨跌会混入换月价差。这里只核对价格身份，不构造收益模型或计算策略收益。

也不能统一依赖连续序列的pre_close字段修复：2022-12-19映射到MA2305时，连续记录昨收为2567，原合约昨收为2616，而当日两者收盘同为2571。2026-09-28的连续昨收又与新合约前日3191一致。因此抽查已发现跨换月的昨收语义并非可未经核验地等同同一合约前收；不能悄悄替换后当作已验证信号。

主力1642条OHLC边界、正价格、成交及持仓非负检查没有异常；但oi_chg缺1514条，不能填零或称完整持仓变化序列。原始样本中三个合约上市首日pre_close为空，不能计算该日跨前日变化；MA2610在2026-10-15成交量为0，O/H/L为0而收盘及结算为3517，属于需要显式处理的无成交记录，不能当普通可交易OHLC。该日MA2610已经不是主力，对所核对的182个映射日一致性没有影响。

后续如研究商品变化，应固定在同一月份合约内比较相邻日价格，并事前明确选择该合约的信息截止时点。只消除拼接价差还没有解决事后选主力的问题；当日主力映射的选择时点不能自动视为收盘前已知。原始价格、缺失、零成交和换月状态须分别保留，不用回填或期货复权序列悄悄替换。

## 3. 时间：交易结束不等于接口当时已有数据

[Tushare更新说明](https://tushare.pro/document/1?doc_id=108)把期货日线描述为盘后更新。这不能支持原提案T日15:00截点直接使用T日日线。网页没有提供每天入库完成的准确时刻；当前连接器元数据虽给出较具体的常规更新时段，也不能替代每条历史记录的首次可得凭据。

[日线字段](https://tushare.pro/document/2?doc_id=138)、[主力映射字段](https://tushare.pro/document/2?doc_id=189)、[合约目录字段](https://tushare.pro/document/2?doc_id=135)均未提供逐条首次发布时间、历史版本及修订记录。交易日期、上市日期或交易时间描述不等于供应商发布时间。今天能取得这些值，只能证明今天返回的历史覆盖，不能证明当时已经返回相同值。

[郑商所夜盘细则](https://www.czce.com.cn/cn/uploadfile/2018/11/09/20181109184247707.pdf)规定交易日自夜盘开始至日盘收市，夜盘集合竞价形成该交易日的开盘价。因此T日日线包含归属T的前一夜时段；T日15:00之后的夜盘不得加入T信号。[甲醇业务细则](https://www.czce.com.cn/cn/uploadfile/2024/02/07/20240207154824122.pdf)列出21:00—23:00夜盘与截至15:00的日盘，并允许调整或暂停；本轮未取得全历史逐日夜盘安排，不能把一般交易时段当作每一天的证明。

**使用前一个期货交易日的数据，可以成为保守运行约定，但不是严格历史可知性证明。** 它通常避开当日盘后更新等待，仍不能排除历史修订、补录和主力映射回写。必须按期货开市日历找前一日，不能简单减一天；2020-01-02所需的2019-12-31甲醇行情不在本次授权价格范围内，没有擅自补取。保持15:00截点意味着不能自动改为当晚决策；如需调整信息截止时点，应另行明确。

本轮因此对时点结论标为：当日15:00使用不获文档支持；前一交易日口径可供评审；严格历史首次可得及修订历史未证实。没有把未证实改写为“历史数据一定存在前视”，也没有声称滞后一天就消除了全部问题。

## 4. 平台与剩余工作

当前DFLS公开期货契约和适配器限定AU/SHFE，不能直接用作MA/CZCE的正式数据准备。本轮沿用既有客户端做获准上游探测，没有绕过限制构造正式研究输入，也没有先行开发甲醇适配。

若继续，建议先评审两项具体口径：

1. 保持T日15:00决策，甲醇输入最多使用前一完整期货交易日，接受并披露无法证明全部历史版本这一研究限制；若需要严格历史版本证明，当前这些接口不够。
2. 选定合约后按该合约原始价计算变化，明确滞后映射的使用及未知发布时间限制，不直接使用连续收盘涨跌。是否增加按前一日持仓量选合约，是另一种输入设计，不能把本次四个样本当成全合约截面。

两项口径获确认后，才值得申请补齐其余18个映射合约原始日线，并提交DEV接入设计。按每合约一次、单合约有效期通常不足2000条的请求方式，**补齐已识别18合约的名义基础估算为18次**；这不含失败、重试、补预窗口、重验缺口或全合约持仓量面板，最终额度需随请求清单确认。本轮不借用原股票执行预窗口剩余额度，也不自动发起第9次调用。

DEV最小范围是MA/CZCE强类型数据契约、合约身份与日历绑定、原始日线/必要映射适配、质量及覆盖验证、明确可用时间约定。无须为此改变股票费用、TXE执行、年度目标，也无须先加分钟行情、持仓排名或公告能力。这里是下一步评审内容，尚未授权实施。
