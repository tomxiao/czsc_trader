# S014 甲醇接入方案评审

日期：2026-10-18。身份：RSCH。状态：方案评审完成，待批准具体口径与DEV实施范围；未修改平台、调用数据或启动模型/账户。

**建议采用“决策日前一个完整期货交易日的主力映射＋该月份合约两天的原始收盘价”。平台只新增两个甲醇数据集，复用现有prepare/fetch。** 该方案可以消除跨合约价差混入价格变化的问题，并落实约定的一日滞后；不能恢复供应商未提供的历史发布时间和修订版本。当前自然日日历还缺一条，正式准备仍有阻塞。

用户本轮授权仅为评审：明确时点限制、换月处理和最小平台修改范围；费用、执行和年度目标不变，不新增数据调用或模型、账户实验。本文件中的字段、规则和测试都是待实施规格，不代表已存在能力或已通过测试。

## 1. 固定信息时点与合约选择

沿用方案中的股票决策日T、15:00 Asia/Shanghai截点，次一股票交易日按原约定执行。定义：

- P：严格早于T日期的最近一个CZCE开市日。
- Q：P之前的最近一个CZCE开市日。
- M(P)：供应商交易日期为P的甲醇主力映射。
- K：M(P)指定的月份合约。
- C(K,D)：月份合约K在D日的原始收盘价。

拟研究的商品一日价格变化为：

`r(T) = C(K,P) / C(K,Q) - 1，K = M(P)`

这是一项历史价格信息定义，不是已验证的收益组件，也不是可交易期货账户收益。**分子与分母必须来自同一K，映射和两个价格日期均早于T。** K在Q是不是主力不影响取价；只要取的是当时已上市同一合约的有效记录。

选择M(P)而不是M(T)，是因为本方案只允许使用前一完整期货交易日的信息；并不声称M(P)在P日开盘前可知。本方案也不额外使用M(Q)选仓：那会变成“在商品价格变化发生前先选合约”的另一问题，增加滞后，不是本次待研究的股票决策时已有商品信息。供应商历史映射后来是否修订，仍未证实。

### 换月发生时怎样处理

当M(P)与M(Q)不同，记为换月；仍取新K在P、Q的两条原始价，不把旧合约Q日收盘接到新合约P日。保留换月标记，供后续研究分开报告，不自动排除换月样本或修改阈值。

已核查的2026-09-28换月中，新合约MA2611在前一交易日9月24日收盘3191，9月28日收盘3249；旧合约MA2610在9月24日为3513。9月29日股票决策若使用该变化，应比较MA2611的3191与3249。9月28日15:00不能提前使用这组P=9月28日的完整数据。具体T/P/Q由日历核验，不按自然日减一。

不使用MA.ZCE连续收盘的相邻比值，也不以连续pre_close代替C(K,Q)：上轮已发现2022-12-19连续pre_close为2567、原合约为2616。不得先把原始行情筛成“每天主力的一行”，再对筛选后的价格shift；那会丢掉换月所需的新合约Q日行情。

## 2. 可用时间必须可执行，且明确只是约定

当前官方资料和返回字段只支持盘后更新描述，没有逐条首次可得时刻、当时版本或修订链。这次评审不再次联网查询，沿用[已保存的上游说明核查](../20261018_methanol_feasibility/others/source_review.json)。

建议将新数据集的使用规则命名为`NEXT_CZCE_SESSION_CLOSE_V1`：源日期D的记录，**约定从下一个CZCE开市日15:00才可用于此日频研究**。这一时刻是人为设定的最早研究使用时间，不是供应商实际发布时间。当前报告中的“不支持T日15:00使用T日数据”，不等于已证明所有历史P日记录在次日必然存在且未修订。

技术落地要求：

1. 原始日线和映射均保留Date，并显式增加AvailableDate，按完整CZCE日历计算下一开市日15:00；统一Asia/Shanghai时区，与股票DecisionTime一致。元数据显式指定`availability_time_field=AvailableDate`，不允许默认退回Date。
2. 同时记录`availability_basis=DECLARED_POLICY`、`historical_publication_verified=false`、`historical_revision_history_verified=false`、规则版本，以及本次取得数据的时间与证据身份。本次取得时间不能冒充历史可用时间。
3. 消费时先按T确定P/Q、按M(P)确定K，精确连接两条行情，并检查所有输入的AvailableDate不晚于T的15:00，源日期符合P/Q。不得用通用“最近一条可得记录”偷偷替代缺失P。
4. 现有`align_temporal_frame`只接受按可用时点单值的序列，多合约日线不能直接传入。先完成上述逐日K/P/Q组装，再使用单值对齐；本批次建议精确会话对齐，不使用会自动延用旧值的as-of方式掩盖缺行。
5. 未来若用于实时流程，实际到达时间也必须满足截点；迟到或缺失不能因历史规则允许就假定已到达。实时运行接入不在本次最小实施范围。

完整T日日线可能包含归属于T的前一夜交易；T日收盘后的夜盘不能加入T决策。即使晚间能取得T日日线，也不在本次方案中把决策时点从15:00挪到晚间。后续若改变信息截点，应单独评审。

**需要用户确认的研究限制是：采用上述滞后可用约定，但不将结果表述为已证明严格历史可知性。** 若要求逐条历史首次发布和版本证据，现有接口及本轮材料不足，接入本身不能解决这一点。

## 3. 起始两日、日历缺口与缺失行为

### 不自动扩展2019预窗口

计算2020-01-02的商品变化，需要前一日P及更早的Q，即按当前日历线索为2019-12-31和2019-12-30，后者仍须相应日历来源确认。不是只补一天就够。原股票执行预窗口授权不能挪作甲醇授权。

最小方案建议维持2020起的甲醇数据范围：2020-01-02和01-03新增商品信息不可用；按现有日历，最早可能可用的决策日为2020-01-06，使用01-03/01-02同合约价格，仍取决于实际数据校验。**评价、BuyHold和年度门槛仍从原2020研究起点计算**，不得截短评价期或把不可用信号填零。后续模型如何处理新增信息未就绪状态另立研究设计，本轮不指定买卖行为。

若用户希望首日商品信息齐备，必须另行批准2019相关甲醇价格、映射和日历范围。这是可选扩展，不是本轮自动请求。

### 已发现的正式准备阻塞

上轮CZCE日历缺2022-12-31。当前DFLS的TRADING_CALENDAR要求请求区间逐个自然日齐备，因此原样导入会失败。已验证1642个开市日与主力日线/S014日期相等的事实仍成立，但不能据此宣称自然日日历可以正式发布。

建议保留现有完整性校验。后续另获调用授权时先针对缺日核查或取得有来源的修正；仍不能取得时如实阻塞，返回数据方案评审。不凭“周六应休市”造行、不用SSE日历替代、不把全局日历规则放宽。读取当前已保存证据不产生新的调用，但也不会消除这个缺口。

### 必需输入异常的处理

| 情况 | 拟定行为 |
| --- | --- |
| 必需的M(P)、K在P/Q的记录或日历缺失 | 明确不可用/准备不完整，不选另一个日期或合约补位 |
| 错品种、重复键、非法价、映射指向尚未上市或已到期合约 | 明确失败，保留错误身份；不取第一条、不静默清洗 |
| 源数据明确Volume=0但保留正Close/Settle | 作为“没有成交的原始记录”保留；这一日不能作为本价格变化的有效端点，不伪造正常交易 |
| 期货上市首日无历史前价 | 不使用供应商pre_close修补；没有真实Q行则该变化不可用 |
| oi_chg缺失 | 本最小契约不要求该字段；不补零，不声称可用于持仓变化机制 |
| 已知起始预热不足 | 显式报告未就绪前缀，保留完整股票评价期；不改变年度目标 |

“数据记录齐备”“某价格变化可用”“策略通过年度目标”是三个判断。无成交记录可以是有效原始观察，但不是有效成交价格变化的两个端点；数据发布READY也不等于组件或策略通过。

## 4. 最小平台修改范围

建议仅新增两个Dataset取值；名称为待DEV落实的建议名：

| 数据集 | 请求与输出语义 |
| --- | --- |
| FUTURES_CZCE_METHANOL_DAILY | 一次DataRequest明确一个MA月份合约（如MA2611.ZCE）及源日期范围。字段至少Date、Contract、ListDate、MaturityDate、Close、Settle、Volume、Amount、OpenInterest、AvailableDate。Close保持未复权原价，Volume=0原样保留，使用者须检验端点是否有成交。 |
| FUTURES_CZCE_METHANOL_MAPPING | 请求固定MA.ZCE及源日期范围，输出Date、ContinuousSymbol、Contract、AvailableDate。映射只用于合约身份，不发布连续价格或自动合成回报。 |

使用上游已核实代码MA.ZCE及MA加四位年月的.ZCE原合约；交易所元数据为CZCE。不额外引入MA.CZCE等同义写法。原合约还须与目录核对身份和有效期，不能仅靠正则通过。合约目录作为provider内部依赖及证据保留，不新增第三个公共目录接口。

最小日线不要求O/H/L、pre_close、oi_chg：此次主问题只需要同合约收盘，保留成交和基本校验字段。上游原始返回及已有O/H/L异常作为来源证据保留；不把无成交时O/H/L=0改成收盘价，不套用股票OHLCV清洗来创造行情。

| 位置 | 必要修改或复用 | 边界 |

| dataflows/contract.py | 新Dataset枚举及针对性强类型请求校验 | 拒绝非MA/错误合约种类，复用DataRequest/PreparedDataRef，不新增公开查询方法 |

AvailableDate应在新provider及其输出校验中显式实现，不改全局默认时间规则来影响已有数据集。已有DataTemporalContract可承载字段映射；当前没有理由先做全期货通用框架、修改全局数据契约版本或迁移黄金资产。若DEV实施发现公共类型确有不足，应带具体阻断返回评审，不预先扩大工程范围。

## 5. 探测证据如何复用，后续调用如何估计

现有探测文件已经发布为不可变材料证据，但不是PreparedDataRef。新增MA契约实现后，DEV可通过已公开的ProviderBinding/ProviderConfig提供一个**明确选择、无网络的证据读取provider**：

1. 校验每份EvidenceRef、文件哈希、请求账户来源标识、合约、字段和日期范围；绑定一个明确证据清单及转换版本。
2. 从清单读取并转换标准表/元数据，经正常prepare校验、发布，取得PreparedDataRef，再由fetch读取。
3. 缺证据、范围不足或哈希错误就失败，不自动联网补齐，也不伪造新的供应商获取时间。

当前ProviderConfig.bindings显式提供时会替换默认绑定，不是追加。离线上下文须显式列齐本次用到的数据集和日历绑定，不能假定未列出的依赖会从默认在线provider补足。

这是显式离线来源，不是在线失败后的兜底。已有4个原合约、映射和目录可复用，不必为同一证据重复付调用成本；日历缺口仍会阻断正式准备，不能因离线导入而绕开。

目前还有18个映射原合约未取回；逐合约补齐的基础估算仍为18次，不含重试。**完整接入并非“再18次就一定够”：还需处理日历缺口，首日全信息若要求2019预热则又有新增范围。** 下一次申请须列清请求清单、失败计数和最高额度；本轮0次调用、余额仍0。不得使用原股票预窗口剩余次数。

原始合约表可以保存完整合约有效期内的已授权日线，方便Q即使尚非主力时仍可取价。需要哪些合约可依据全期映射制定下载清单，但不能用该清单的未来成员身份作为某个历史T的信号；历史选择只使用M(P)。为了避免为最后一条源数据越界获取下一交易日日历，可将正式消费所需源日期终点限定到最后决策日前的P，并单独保留原探测尾行作证据，不伪造其AvailableDate。

## 6. 实施后的聚焦验收规格（本轮未执行）

1. 错合约、错交易所、连续码误用于原合约请求、超有效期、重复键、非正价和负成交数均明确拒绝。
2. 请求一合约不会拉取全部活跃合约；预算外HTTP、自动重试或隐式日期扩张不发生。
3. 用已保存换月案例构造离线夹具，证明取的是新K在Q/P两日，不是旧K(Q)与新K(P)，且不依赖连续pre_close。
4. P/Q按CZCE开市日求得，覆盖周末、假期、股票与期货日历不一致的显式拒绝/未就绪路径；禁止自动退到更早现存数据。超出本批次已验证同日历范围时，不默认跨市场继续有效。
5. Date与AvailableDate分别验证，T日记录不能进入T日15:00；精确使用P/Q，不把可用时间文字说明当执行限制。若规则下没有下一CZCE日历记录，明确缺口，不推算。
6. 起始两日未就绪被记录，不缩短股票评价；缺少Q或无成交端点不产生伪造r。零成交原始记录的保留与禁止当有效端点分别测试。
7. 既有缺2022-12-31日历夹具必须拒绝，证据损坏和范围不符必须拒绝；证据导入与发布后fetch均零网络。
8. 新MA provider、契约与时间对齐的相关测试通过；现有AU测试保持通过。无需为本轮纯方案运行仓库级回归。

这些是数据及实现的正确性检查，不是新增收益硬门。后续组件价值与账户年度目标仍分别验证，不把接口测试通过当作可进入下一研究阶段的绩效证据。

## 7. 评审结论与待决定事项

方案边界可以收敛为：**两种甲醇数据集＋显式可用时间＋单合约两日原价，保留日历完整性和异常语义；不扩全期货平台。** 数据权限已具备，但日历缺口、其余原合约及历史修订限制不会因为新增适配器自动消失。

建议下一步确认本文件的时点约定、M(P)选K和同合约Q/P计算、初始两日未就绪口径，以及两个数据集的DEV范围；若确认，再授权DEV做离线实现与聚焦验证。联网补齐应单独给额度，模型/账户继续另行授权。当前只保存评审材料，未将“同意评审”记作同意实施或接受历史可知性限制。

费用仍单侧0.1%，研究使用后复权股票行情，原限价买入/开盘卖出及跌停一价位、100股单位、10万元连续账户、固定BuyHold均保持。每自然年BuyHold正收益时策略至少其1.5倍，否则严格正收益；每年回撤幅度严格小于BuyHold；2026截至10月15日直接计入；60×闭合数÷1642≥3。不改变任何年度目标或历史候选资格。
