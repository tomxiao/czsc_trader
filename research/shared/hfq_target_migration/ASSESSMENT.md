# 冻结策略后复权输入与目标仓位契约迁移评估

评估日期：2026-11-08。身份：RSCH。基于分支 `codex/dev-adjusted-replay` 的平台提交 `7b36dd21d`。

本轮已完成指南修订和只读迁移盘点。未修改冻结包、候选、安装记录或账户，未运行研究回放，未访问生产。本文是迁移工作评估，不是升级批准或等价性通过报告。

## 结论与范围

本地有8个登记且有安装记录的冻结版本，均声明主行情 `analysis_price=RAW`、缺少当前必填的 `execution_policy`，且实现仍输出订单或订单腿，不能直接在新版契约下运行。主行情声明为RAW不代表原金融信号都用RAW：大多数已有HFQ辅助输入，必须逐项区分其观察与执行用途。

盘点依据为 [策略注册表](../../../strategies/registry.json)、各版本记录及 [本地安装记录](../../../strategies/deployments/)。本地8版包括7个A股版本和1个美股版本；这不是prod活动账户数量，也不据此重新解释此前“七个账户”的验收范围。

7个A股版本可按现有EC执行政策开展迁移验证，是否等价仍待实测；S018存在分阶段入场执行表达缺口，须先解决，不能替换为另一套资金规则。

## S018需要补齐的执行表达

[原策略](../../../strategies/S018/releases/v1/src/strategy_runtime/strategy.py)以入场时可用现金乘分组分配比例锁定 `entry_budget`，首单使用其50%；持仓后满足最早加仓日及MU、SOXX修复条件，且只有一次买入成交时，再使用原预算减已买成本补仓。预算与首次下单时点绑定，不能改成随权益重新计算。

当前 [EC规划入口](../../../packages/execution_channels/src/execution_channels/planning/__init__.py) 的 `signal_cash_fraction` 建周期后，把后续非零目标视为继续活动并沿用锁定量/预算；不能直接用目标从0.5变为1表达上述第二阶段。`TARGET_POSITION` 按当前权益和参考价计算数量，可能引入再平衡，也不等价。`INTRADAY_OVERLAY` 承担另一类底仓轮动，不能据名称相似套用。

因此建议向DEV提出具体需求：在目标仓位输出边界内表达分阶段入场，EC持有原始预算并承担费用、取整、股数及成交反馈处理，策略只表达入场、等待、确认增加仓位和退出。设计须明确目标的比例基准、部分成交、未成交、持仓对账及重启续接语义。不能由策略继续计算现金或股数，也不能将交易命令藏进解释字段。该项需要单独授权DEV评审与实施，本轮不改平台、不改变S018交易规则。

## 数据、身份及状态迁移

- 数据继续经DFLS取得。分别保留供应商、获取方法、可用时点及内容身份。HFQ主行情、辅助行情和历史执行行情使用一致价格尺度；对应价格限制也须一致。来源或获取方法改变时，先比较数据，再比较信号，避免把数据变化误归为策略修改。
- A股ETF和Futu的实际权限、覆盖及完整性需在迁移验证时确认，本轮没有进行在线供应商请求。DFLS直供和自行计算可能有不同成交量含义，特别影响S001、S007及容量约束；HFQ标签也不自动保证总收益或历史时点可得性。
- 新实现通过研究候选和正式原地升级入口更新发布身份，保留旧源码、历史选型及证据。平台接口见 [TDR冻结运行升级](../../../src/czsc_trader/README.md)，不直接改写版本、冻结包、注册或安装记录。
- PTE正式输入须采用当前 `FormalV4Inputs` schema 3，独立绑定RAW执行参考价；SRT只绑定HFQ观察。此schema与冻结包 `runtime_binding.json` 的schema 2属于不同文档，不可混用。
- S001/S002/S007/S011/S015的 `locked_quantity`、`had_position`，S003的 `core_quantity` 中承担执行职责的状态迁入EC。旧负值哨兵不得直接写入新锁字段，应依据旧状态和已确认账户事实显式映射；含预算或分阶段状态的账户另核对成本、锁和未完成订单。
- PTE已有显式状态映射入口，见 [账户维护实现](../../../packages/paper_trading_engine/src/paper_trading_engine/v4_account_maintenance.py)。源码升级、输入重建、账户状态映射、生产重绑及生效分别留证；本次未读取生产状态，不能提前断言每个在途账户可以直接续接。

## 验证设计与迁移顺序

| 验证层次 | 比较条件与结果要求 |
| --- | --- |
| 金融信号与状态 | 固定同一可得HFQ输入，逐时点比较原金融规则与新目标表达，覆盖前缀、入场、持有、退出和阈值边界；目标表示发生变化时比较经济含义，记录明确映射，不机械比较原0/1与新分配比例 |
| 模拟执行规则 | 对同一RAW参考价、确认账户与费用，将旧公式作为隔离对照，逐项比较EC生成的报价、数量、订单依赖及预算/数量锁；覆盖资金不足、部分成交、未成交、退出和重启；旧代码不接回正式运行链路 |
| 新历史账户 | 在HFQ价格和整数模拟单位下验证策略与买持使用一致合同、账本连续及阻断语义；保留新结果，不要求与旧RAW回放净值相等，不将新结果直接称为原绩效等价 |
| 技术交付与状态映射 | 新候选与冻结包同模型行为等价；隔离PTE使用HFQ观察、独立RAW执行输入，验证状态映射、重绑和恢复。生产授权与模拟交易资格另行处理 |

推荐先用S002验证通用周期规则，再处理S001两版、S007、S011；随后处理S015的HFQ分钟中心与预算规则，再处理S003的依赖订单。S018先完成执行表达的DEV评审，具备原规则表达能力后再迁移。

工作容量为8版源码/定义迁移及逐版技术验证，S001两版可复用共享实现对照，但保留各自配置结果。仅做与变更相关的聚焦验证，不在本轮启动参数搜索、全仓回归或重跑全部阶段四。正式回放窗口、所需账户数与预计耗时在实施前按已有资产及用户批准范围确定；本评估不虚报计算预算或已通过数量。
