# PySR 引入验证计划（历史案例）

状态：已按 [METHODS EX01](../experiments/METHODS/20260926_PYSR_EX01/04_conclusion.md) 与 [EX02](../experiments/METHODS/20260926_PYSR_EX02/04_conclusion.md) 执行；结论为 `DO_NOT_ADOPT_NOW / DEVELOPMENT_ONLY`。本轮只比较 S003、S007、S008；不读取各批次封存期，不改变冻结策略、平台依赖或生产账户。历史案例及其组件已经被研究员看过，回放结果只能用于判断工具是否值得进一步独立验证。

## 决策问题

在相同的因果输入和固定计算预算下，PySR 搜索出的非线性公式，是否比简单线性规则更能识别**扣除成本后仍可参与的收益**？代码编写速度、公式数量和样本内拟合改善均不足以支持引入。

## 冻结的工具对照

1. 特征先按拟合期统计量补缺、标准化并裁剪到 ±5；评价期不得重新估计。标签结算日必须处于拟合期内，避免边界泄漏。
2. PySR 固定版本、种子、单线程、输入、算子 `+ - *`、最大复杂度 9、固定迭代预算；保留完整 hall-of-fame。基准为同输入的固定正则线性回归（Ridge，alpha=1），无评价期调参。可另列既有冻结规则，但不假称历史研究与本轮拥有相同搜索预算。
3. 先看评价期 RankIC、MSE、年度方向及与线性基准的预测差异；再用同一事先定义的仓位映射检验收益。S003 在相同事件频率下比较事件选择，沿用往返 2.4/12bp；S007/S008 都执行 T 日信号、T+1 开盘成交，使用各批次成本与完整账户规则。
4. 记录公式、复杂度、实际搜索量、输入文件身份、数据切分、全部尝试和失败。对搜索偏差做保持时间结构的标签错位负对照。任何模型或映射调整都必须新建后继方法实验。

## 裁决

PySR 若不能产生与线性/历史原型不同的决策行为，或其开发期顺序评价的净账户收益、机会捕获和年度稳定性没有可靠增量，则暂不引入。若至少两个不同机制案例显示成本后稳定增量，且负对照不能产生类似结果，只申请**独立、事先冻结的验证**；仍不直接加入项目依赖或宣称新 Alpha。正式候选必须另走策略实验、TXE 账户及 CIO 合同。

执行结果和缺失的验证层级记入新的 [METHODS 实验](../experiments/README.md)；本计划不授予封存期读取、平台修改、冻结或 PTE 权限。
