# 阶段四自检执行效率验证

日期：2026-10-22。开发分支：`codex/stage4-selfcheck-efficiency`。比较基线：`a20f7a34`。

## 交付范围

- `ExecutionResources`统一可并行入口的默认预算：本机逻辑核数的70%，向下取整且至少1个；显式资源覆盖默认。
- `open_research_execution`使连续账户计算及证据序列化共用一个有界进程池，正式证据由主进程原子发布。
- 显式CREATE／RESUME检查点保存已完成计算与发布引用；恢复核验实现、请求、数据和实际证据，不自动重试未知结果。
- `assemble_delivery`返回`DeliveryAssemblyResult(receipt, validation)`，一次完成组装、FULL复算及安装后完整性复核。
- 独立`validate_delivery`重新认证当前字节；账户认证采用有界并行和单次调用内的紧凑缓存。
- 补充执行进度、分段耗时、恢复命中、文件读取及哈希统计。

公共契约与使用示例见[TDR说明](../../src/czsc_trader/README.md)、[SRT说明](../../packages/strategy_runtime/README.md)。
旧`EvaluationResources`、`EvaluationRequest.workers`及重复进程池调度实现已移除。历史研究脚本、证据、交付和策略发布包保持原样，后续实验按当前API编写。

## 验证口径

聚焦功能检查覆盖资源边界、真实账户计算／发布、五类账本等价、跨批进程池复用、工作进程退出、驱动进程异常退出、检查点损坏及恢复、发布状态、交付图完整性、确定性复算和冻结调用方。
平台源码参与评价环境身份；修改前后比较经济账本和数值，同时核验各自身份，不要求不同实现具有同一环境哈希。

性能工作量固定为3个合成候选、每个33个费用场景、每份账户5个交易日。调用实际TDR/SRT/TXE链路，计时包含批量计算、显式发布及进程池关闭；不含解释器导入、初次合成数据准备及比较摘要生成。
固定8个工作进程、每进程1个原生线程、随机种子0。新实现不启用检查点，恢复命中为0，避免用少算任务制造提速。
小型合成窗口测量主要反映调度、传输及发布成本，不外推434日阶段四总耗时。

原始测量脚本、配置、账本比较摘要和结果保存在仓库临时目录[性能验证材料](../../.tmp/stage4-performance/)。
这些是工程验证材料，不是新研究实验或正式策略证据；清理临时目录不会影响平台及正式研究交付。

## 测量结果

### 同工作量批处理

初轮共享机器观察保留在`summary.json`。最终结论采用固定8个工作进程、无本轮其他测试负载的三对交错复测，顺序为旧→新、新→旧、旧→新。

| 版本 | 第1轮 | 第2轮 | 第3轮 | 中位数 |
| --- | ---: | ---: | ---: | ---: |
| 基线 | 35.8180秒 | 35.9922秒 | 37.8064秒 | 35.9922秒 |
| 新版 | 18.3809秒 | 19.3470秒 | 19.7836秒 | 19.3470秒 |

中位耗时减少46.25%。六轮共594份账户全部计算与发布成功，重读实际证据后，指标及五类账本完全一致；统一经济摘要为`abe65c1e39b089efc7237f04824211ed60c561ad6f54edc9ad4a44cabf8c70e1`。
新版每轮只启动1个进程池，完成198项任务（99项账户计算、99项认证序列化）；失败、未知、计算恢复命中、发布恢复命中均为0。
操作系统后台负载未控制，没有主动清空磁盘缓存。结果见[交错复测汇总](../../.tmp/stage4-performance/quiet-summary.json)。

### S015真实交付FULL复核

对既有`S015/ASSESSMENT/1`只读复核，两版均返回FULL PASS；交付身份为`020663f560ebd639bf0f01eeca03917e44f96f9d4f22bdf2abae64910374943f`。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 校验耗时 | 1,240.03秒（20.67分钟） | 444.79秒（7.41分钟） |
| 唯一交付 / 引用访问 | 8 / 9 | 8 / 9 |
| 读取并哈希的文件次数 | 16,351 | 19,702 |
| 哈希字节数 | 27,301,633,334 | 32,929,313,175 |

本机16个逻辑核，新版默认并发预算11。新版完整认证3,351份账户，随后完成SE复算及最终文件复核；账户认证160.67秒、SE复算96.99秒、最终复核19.33秒。额外文件读取来自工作进程认证及主进程对当前字节的复核，没有以跳过完整性检查换取速度。

这次端到端观察耗时减少64.13%。修改前测量与部分开发检查共享机器，新版又受操作系统文件缓存影响，且两版并发实现不同；这是一次真实规模观察，不能当作隔离条件下的固定加速比例。

修改前观测到父进程峰值工作集约27.74GB；新版父进程峰值约6.03GB，0.5秒采样的进程树工作集总和峰值约7.21GB。前者不是旧版完整进程树峰值，采样也可能漏掉瞬时峰值，不据此计算严格的内存降幅。

结果见[修改前](../../.tmp/stage4_delivery_baseline.json)、[修改后](../../.tmp/stage4_delivery_after.json)。真实规模测量完成后仅补充`PACKAGE_LOAD`进度与排他计时；该观测补丁通过下述46项聚焦复验，未再次执行完整规模计时。

## 边界

- 70%是并发预算，不是CPU利用率保证。不同顶层会话没有整机统一调度；同一上下文禁止嵌套会话及回调重入。
- 只对完整落盘且核验通过的计算结果承诺恢复；尚未保存或无法确认的任务仍由调用方显式决定是否重试。
- 计算工作进程丢失返回UNKNOWN；证据序列化失败且主进程尚未写入时返回FAILED；提交无法确认时返回UNKNOWN。
- 历史WinError6未复现并定位，不能把本次故障注入通过称为已查明其根因。
- 技术检验的并行回放采用统一默认预算；PTE隔离场景仍按既有顺序执行。本次未改变PTE运行账户或生产状态。
- 本轮为聚焦验证，没有执行仓库级全量回归、发布、部署、合并master或远端推送。
