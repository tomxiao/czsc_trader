# 回测全链路优化验证

日期：2026-10-22。身份：DEV。分支：`codex/stage4-selfcheck-efficiency`。比较基线：`33e1fad8`。

## 范围与实现

本轮保持公共契约、API、schema、策略逻辑和执行规则。优化范围为 TDR、SRT、TXE 内部的重复复制、时间定位和逐日遍历；未引入 vectorbt、全局缓存、磁盘缓存或认证降级。

| 模块 | 内部改动 | 保持的边界 |
| --- | --- | --- |
| TDR | 基准与图表先建立不携带 `attrs` 的数值容器；同次 BuyHold、MA 计算复用估值表 | 原始行情与质量证据保留，日期及输入认证继续执行，返回值不污染源数据 |
| SRT | 按已验证的有序唯一索引定位当前行，直接读取前一期目标仓位，移除每日整列 `shift` | 首期前值为 0，显式动作优先，WINDOW／CONTINUOUS 语义及必要的策略输入隔离保留 |
| TXE | 接纳数据时只复制数值；收盘价及分钟区间使用有序索引定位；估值账本采用数组遍历 | 成交、费用、现金、停牌、仓位、估值来源及异常语义保持；无订单时跳过分钟切片 |

复用限定在单次调用或当前账户内存。未增加频繁读写磁盘的链路；必要的正式证据与报告写入保留。性能收益主要来自计算路径，不能将本轮结果解释为磁盘开销或峰值内存大幅下降。

两处 SRT 数据准备未合并，避免扩大到实例状态、输入认证和缓存生命周期的重构。生产账户、冻结策略发布包、正式研究证据和历史回测输出均未修改。

## 聚焦验证

聚焦检查共 **243 项通过**，未执行仓库全量回归。

- TDR：79 项。覆盖真实公共回测入口、独立报告、基准契约、交易单位、行情认证、图表、不可深复制的证据元数据、源数据与返回值隔离、非法日期。
- SRT：37 项。覆盖公开运行契约、运行时 v2 及执行语义；包括两种历史模式、第一期、仓位增减与保持、分数仓位、显式动作、覆盖型动作、缺失信号日期及输入隔离。
- TXE：127 项。覆盖历史账户与逐日执行、价格区间、费用与现金、停牌、分数仓位、交易单位、分钟路径、覆盖型交易、快照无参考价格、源数据隔离及禁止证据深复制。
- 修改涉及的 Python 文件 Ruff 检查通过；独立只读复核未发现需修复问题。

## 性能与等价性方法

旧版从基线提交归档至临时目录，新版使用本轮工作区；独立断言 TDR、SRT、TXE、SE、DFLS、SM 实际导入路径。网络及 DFLS provider 拉取禁用，双方使用同一 SQLite 快照，SHA-256 为 `54f78f7c99885dd88d0f163a5555653121caf4b4bcdad449b22faa75026b0baa`。

真实策略为 C0031 与修复后的 S011-v1，标的 `159326.SZ`，窗口 2025-02-06 至 2026-10-21，共 415 个交易日，初始现金 100000、交易单位 100。账户单进程、原生线程 1。每版重复三次，版本交错顺序为旧1、新1、新2、旧2、旧3、新3。计时期间暂停本轮其他测试和源码修改；操作系统后台负载未控制，未主动清空系统磁盘缓存。

完整计算包含策略回放、基准和 SE 审查；完整交付另计完整报告渲染及真实写盘。解释器导入、SQLite 副本准备、策略对象加载和事后比较不计时。因此下表为已加载运行环境中的业务链路耗时，不是从启动命令到退出的冷启动总耗时。各阶段独立取中位数，阶段中位数之和不保证等于总耗时中位数。

完整计算耗时下降分别为 **19.75%、22.51%**；完整交付下降分别为 **18.83%、20.11%**。C0031 的完整交付降幅未达到拟议的 20% 工程目标，不能报告两策略均达标。没有为了追求该阈值扩展公共契约或增加缓存复杂度。

RSS 每 250ms 采样，包含导入及输入对象，单位为十进制 MB；内存表现基本持平。报告渲染时间略增，写盘仅占毫秒级，不据此声称各阶段均提速。

12 次真实账户运行均与历史五类账本及指标一致。每策略旧新版全部 **21 份交付文件逐字节一致**，包括策略与基准的 14 份 CSV、指标、审查、manifest、观测、两份 HTML 图表及 Markdown 报告；未排除 manifest 或放宽文件比较条件。

## 批量执行

短窗口负载为 3 个合成候选 × 33 个费用场景 × 5 个交易日，每轮 99 份账户。双方均用同一 session API、8 个 worker、每 worker 原生线程 1，关闭检查点，实际执行计算及发布，计入进程池退出。

三次中位耗时 **19.43472 → 18.65729 秒，下降 4.00%**。六轮共 594 份账户的五类账本及指标完全一致。这是短窗口并行回归结果，不能外推真实长窗口批量提速比例。

另以真实 C0031、同一 415 日窗口进行长窗口批量测量：每轮 8 份经济参数相同、场景 ID 不同的账户，分两批各 4 份，固定进程池上限 8、原生线程 1、检查点关闭。逐批调用公共计算及证据发布接口，计时包含 session 建立、两批计算发布和进程池关闭；初始真实输入认证准备、复制及事后比较排除在外。它测量已准备请求的批量执行，不能与上表独立回测完整交付直接相加或比较。

| 真实长窗口批量三次中位耗时 | 旧版 | 新版 | 下降 |
| --- | ---: | ---: | ---: |
| 计算 | 6.594874 秒 | 5.338519 秒 | 19.05% |
| 发布 | 1.226440 秒 | 1.190619 秒 | 2.92% |
| 进程池关闭 | 0.231835 秒 | 0.231612 秒 | 0.10% |
| 总计 | 8.174615 秒 | 6.753560 秒 | **17.38%** |

六轮共 48 份账户，每份 415 日；实际发布证据中的五类账本和回放指标采用规范 JSON 比较，逐字节一致，统一经济摘要为 `b68ec18502b81cdd2466975aae98cedb50131578c27a6fef097a8839721ec95e`。每轮完成 16 项实际任务（8 项计算、8 项认证序列化），复用、失败、未知均为 0。每批只提交 4 份账户，不以进程池上限 8 推断 8 核持续满负荷。

长窗口结果支持真实策略批量链路提速，但仅覆盖一个策略、一个窗口、同经济参数的重复场景，不代表多策略大规模研究的普遍提速比例。原始配置、阶段计时及严格比较摘要见[long_batch_summary.json](../../.tmp/backtest-pipeline-benchmark/long_batch_summary.json)。
