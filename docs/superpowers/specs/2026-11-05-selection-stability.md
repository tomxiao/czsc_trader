# 选型稳定性自检：DEV需求评审与技术方案

日期：2026-11-05。身份：DEV。状态：完成需求评审，待用户批准实施。

需求来源：[RSCH平台需求](../../../research/S018/materials/selection_stability_platform_request.md)，提交`a5f16cc83`。本轮仅增加此技术方案，不修改平台、指南或真实研究材料，不执行研究计算。

## 1. 评审结论

需求可实现，推荐按独立能力增量实施：已有账户批量投影窗口事实，SE按声明规则进行前段选择与后段观察，结果通过现有材料证据附入阶段四。

- 前五项自检、原排序及经济验收政策不变；不改造PBO/DSR。
- 首版只做固定候选集合的回顾性诊断，不开展逐窗搜索或模拟动态换仓。
- 支持A股/美股、日线/M30及已有相同V4观测结构的频率，按实际交易日切窗。
- 支持净年化、净卡玛为首要目标，标准绩效/频率硬门和有序次级指标；不支持复杂Pareto/部分序、压力/参数邻域条件及人工决胜，不删项替代。
- 不调用整套`assess_candidates`或`compare_candidates`，不恢复旧执行会话，不新增策略回放。
- 现有`DeliveryContent.evidence`可承载独立附证，首版不升级schema 15、不修改旧面板和旧交付。

本方案中的“完成”指计算按支持的输入结束，不指研究可信、经济达标或独立验证通过。

## 2. 需在实现中明确的需求边界

### 2.1 窗口事实不是新账户

现有`AssessmentEvidence`的美股/A股V4适配要求账户开头为空仓、现金等于初始资本，不能把继承持仓的窗口塞回该类型。新增窗口事实保留原账户身份、窗口索引和实际起点净值，不创建虚假的新账户或评价ID。

### 2.2 日历固定，覆盖按窗口判断

窗口由显式声明的研究日历确定，并绑定既有输入来源。不得用全部候选的全样本交集生成日历。某候选只缺后段数据时，前段事实和选择结果必须保持不变。

对合法来源中的局部缺日/缺柱，按窗口输出覆盖不足；来源哈希错误、非法结构或身份冲突属于输入错误，不能把损坏文件局部猜读为有效证据。这与正常后段缺失是不同情况。

批量调用将损坏来源单独记为`SOURCE_FAILED`，与合法覆盖不足区分；其他来源可保留已完成事实，但总体只能报告相应部分结果，损坏来源不能提供所谓有效前段事实。请求本身的非法类型、窗口或重复身份冲突则在计算前拒绝。

### 2.3 选择排序和观察排名分开

选择先用硬门筛选，再按声明顺序排序。观察期对选择时锁定的可选集合计算相同目标顺序的排名，不以观察期是否达标再筛选；条件保持情况另外报告。

后段“排名”是目标排序，不是重新取得全部选择资格。原规则为部分序、人工裁量等首版不支持的形式时明确拒绝，不在本项中偷偷改成单一分数。

### 2.4 首版不接受窗口内重做前五项

规则可以使用标准净年化、净卡玛、回撤以及已支持的频率事实。若原决策依赖费用压力、参数邻域或研究族统计，则本版本返回不支持，不能调用其他自检补齐，也不能忽略这些依赖。

### 2.5 正式附证不自动复制全研究族原账

材料JSON中的来源引用不会自动成为交付包内的递归依赖。默认交付完整窗口事实、规则、结果和来源清单；原账继续保存在既有不可变资产中，并明确该包不是全部原始账户的便携副本。

需要完整原账副本时，调用方显式将账户引用加入交付证据列表，平台按现有机制复制闭包并单列字节和时间成本，不新增打包模式或隐式递归扫描。

## 3. 模块与公开入口

两个业务步骤，三个窄入口；名字为实施建议，正式API在实现评审中固定。

| 所属 | 建议入口 | 职责 |
| --- | --- | --- |
| SE | `project_equity_windows(request)` | 纯数值投影：一份记录观测、全部唯一窗口、所需指标，返回紧凑事实；不读文件 |
| TDR | `project_selection_window_facts(repository, request)` | 批量读取明确的V4账户来源，复用日历与基准，调用SE投影，返回事实、来源及工作统计 |
| SE | `assess_selection_stability(request)` | 只消费窗口事实；逐窗选择、后段观察与汇总，不读文件、不执行策略 |

不再增加“一键计算并保存”“预认证”“结果复验”等入口。发布仍由调用方显式调用`publish_evidence(MaterialEvidenceWrite(...))`，阶段交付使用既有`assemble_delivery`。

SE投影入口是TDR与数值模块的公开依赖边界，避免TDR跨包调用私有函数或自行实现财务指标。RSCH通常只需要TDR批量投影和SE选型分析两个入口。

## 4. 强类型设计

### 4.1 输入

| 类型 | 核心字段和约束 |
| --- | --- |
| `SelectionWindowPair` | 唯一ID、选择期/观察期日期；开始不晚于结束，选择期末早于观察期初；所用显式日历身份 |
| `SelectionMetricOrder` | 指标枚举、方向；原始值排序或显式分箱两种判别类型；分箱复用现有精度和舍入语义 |
| `SelectionRule` | 版本及来源、标准条件目标、频率定义、有序排序键；首键净年化或净卡玛；并列保留 |
| `SelectionWindowPlan` | 完整窗口对清单、日历/数据边界、观察条件、回顾性模式及限制；首版不在平台自动选窗口长度 |
| `WindowSource` | 精确候选/内容身份、V4账户EvidenceRef、声明可比群组；允许显式缺失来源记录，禁止省掉候选 |
| `WindowProjectionRequest` | 候选全集、来源、计划、所需指标并集、明确预算；不含候选全样本达标标签 |
| `SelectionStabilityRequest` | 候选全集、计划、原选择规则、窗口事实集合；不能用排名结果替代前段事实 |

SE纯计算层使用独立来源标识/摘要及事实，不依赖TDR文件系统、候选注册表或EvidenceRef类型。TDR返回的来源清单将SE来源ID与原EvidenceRef一一关联。

目标复用`ResearchTarget`、`FrequencyCoverageTarget`、条件及界限类型，但对scope、metric和bound建立首版支持白名单，拒绝压力/参数类型。类型检查和错误发生在读取重账本之前。

首版支持原始值排序和现有分箱规则，不能为了统一实现强制分箱。次级排序仅限已投影的标准年化、卡玛、回撤、频率中位数、频率Q10及覆盖率。完整历史频率或买持盈利年份专属频率若涉及未实现语义，则明确不支持。

不接收任意Python回调、`eval`表达式或未经类型限定的策略评分字典；不推断调用方未声明的方向、精度或规则。

### 4.2 事实和结果

`AccountWindowFacts`保存：候选/源账户标识、唯一窗口ID、实际起止和覆盖、前收盘起点权益、终点权益、区间收益、年化、回撤、卡玛、频率事实、基准窗口ID、指标状态与原因。逐柱原账不重复嵌入各窗口。

`WindowFactsPanel`保存：候选全集、明确的窗口全集、共享基准事实、逐候选窗口事实及缺失项、指标口径、来源清单与投影统计。不存在的候选-窗口组合明确列为缺失，不以输入数组长度作为分母。

`SelectionDecision`保存：前段目标检查、淘汰原因、完整可选集合、前段排序键、并列最优集合以及选择状态。它不含后段字段。

`SelectionObservation`保存：锁定的选择决策ID、选中成员后段事实与条件状态、固定参照集合、排名区间和不可用原因。

`SelectionStabilityResult`保存逐窗决策/观察、需求约定的计数和汇总、计划/规则/事实摘要、版本与限制；不提供经济“稳定性PASS”或综合分数。

大面板序列化只保存一份事实表，结果用候选/窗口ID关联，不重复嵌入全部来源和指标。JSON采用显式类型与版本并测试往返，不引入新数据库。

## 5. 数值复用和计算过程

### 5.1 可复用代码

| 现有位置 | 复用方式 |
| --- | --- |
| [equity_assessment.py](../../../packages/strategy_evaluator/src/strategy_evaluator/equity_assessment.py)的观测结构、日末值、绩效公式 | 投影已有V4权益及闭合周期；不调用独立审计 |
| [calmar_diagnostics.py](../../../packages/strategy_evaluator/src/strategy_evaluator/calmar_diagnostics.py)的窗口起点和卡玛 | 使用相同前收盘边界及回撤语义；窗口返回完整所需指标 |
| [research_acceptance.py](../../../packages/strategy_evaluator/src/strategy_evaluator/research_acceptance.py)的标量/覆盖/卡玛判定 | 最小抽取不依赖完整候选面板的纯函数；保留严格/包含边界和条件分支 |
| [research_assessment.py](../../../packages/strategy_evaluator/src/strategy_evaluator/research_assessment.py)的频率与分箱 | 抽取共享计数及Decimal分箱；不调用整套Pareto和O(M²)比较 |

若需要抽取共享纯函数，旧调用方保持输入输出及算法语义不变，聚焦验证原五项相关路径；不以此次修改重新定义任何旧指标。

### 5.2 每个候选一次投影

1. 依据独立日历把日期窗口转换为精确索引，去重相同窗口。
2. 每份候选观测只解码一次，生成交易日到逐柱区间的索引、日末净值和按退出日汇总的闭合次数。
3. 所有唯一窗口复用这些索引。收益/年化直接使用起点和终点；回撤初版扫描该窗口要求的实际观测点，不先引入区间树等复杂结构。
4. 频率使用退出次数前缀和。预计算长度F的完整交易日子窗计数，再按窗口索引选取完全落入分析窗口的子窗，计算中位数/Q10/覆盖。
5. 对共享买持只投影一次，以精确基准经济身份、日历、指标口径和窗口集合为复用键；候选源变动不能错误命中。
6. 完成该候选所有窗口后释放其完整账本及解码对象，只保留紧凑事实。

回撤不只取日最低值或日末值：日内先高后低的顺序可能影响结果。首版保留逐柱扫描，只有实测确认为主要瓶颈时再单独评估保持次序的日摘要合并优化。

年化沿用当前V4的252实际交易日公式。`drawdown <= 1e-12`时卡玛保持不可用，不返回无穷大。BAR_CLOSE窗口使用所有应有账户观察点；SESSION_CLOSE使用应有日末点。覆盖检查使用既有输入的实际交易日及观察时点，不按固定每天柱数推算半日市或夏令时。

窗口开头取前一交易日实际收盘权益，账户首日取原初始权益；无该基点时该窗口不足，不取第一个可用点替代。基准独立使用自己的同期起点。跨窗入场、窗内退出的闭合交易仍按原退出日口径计入。

### 5.3 两阶段隔离

内部保留两个职责明确的函数：`select_window(rule, selection_facts)`和`observe_selection(decision, observation_facts)`。前者只获得前段事实，不能访问后段事实、后段缺失状态或全样本资格；后者不能改写选择结果。

投影可以批量完成前后段事实以减少I/O，这不等于允许前段选择使用后段信息。验证隔离依靠类型边界和变异测试，不另加一次影子重算或认证流程。

### 5.4 缺失、条件与并列

- 任一已知硬门失败即可明确淘汰，即使无关指标缺失；其他候选若证据不足且可能入选，整轮不宣布完整赢家。
- 无硬条件的规则用显式无筛选类型表达；有硬条件但全部分支不适用时沿用既有INDETERMINATE，不擅自当作通过。
- 明确淘汰所有候选是`NO_ELIGIBLE_CANDIDATE`，不是技术失败；缺失导致无法选择是`INSUFFICIENT_SELECTION_EVIDENCE`。
- 原始或分箱键完全相同者保留为并列最优集合。排名区间为“严格优于人数+1”至“严格优于人数+并列人数”。候选ID只排序输出。
- 后段只在前段可选集合内按相同目标顺序计算排名，不应用后段硬门筛人。任一必要成员后段排序信息缺失时，完整排名不可用，但保留选中者已知指标和条件状态。
- 可选集合只有一个成员时，可观察其绩效及条件保持，竞争排名标记不适用。
- 保持率按窗口-选中成员计数，输出通过/失败/未知及两个分母；窗口重叠及并列人数不会被包装成独立试验。

状态至少分三层：调用/计算状态、逐窗选择状态、后段条件及排名状态。非法类型、反向窗口、重复身份冲突直接异常；支持范围外返回明确的Unsupported规则错误。读取失败、来源损坏和合法缺失分别保留原因，不能返回假COMPLETE。

## 6. TDR读取和资源生命周期

现有[materialize_equity](../../../src/czsc_trader/research_tools/equity_replay.py)支持V4闭包，但`.payload`每次完整解码；后续构建整套评估事实还会重复投影。新批量入口不在候选×窗口循环中套用此链。

最小调整是复用其身份/依赖检查逻辑，拆出本次批量调用内可共享的只读解码组件，避免复制一套V4协议解析器或新增公开“跳过校验”参数。既有`MaterializedEquity.payload`的隔离语义保持不变。

调用内复用规则：

- 读取、哈希核对以实际来源路径和声明哈希为键；各实际文件每次调用最多读取一次。相同哈希位于不同路径时，仍核对相应路径的声明来源；可共享已解析的不可变内容。
- 来源引用、账户归属、输入和基准经济身份、指标口径进行本次投影必要检查；不做会计重算、策略源加载或数值认证。
- 同一时刻只保留当前候选重账本与必要共享输入/基准的解码内容；共享多群组按明确资源上限处理，不常驻所有原账。
- 新缓存仅存在于一次显式投影调用，完成或失败均释放。现有全局16项`read_ledger` LRU不作为本批次资源策略，不新增永久缓存。
- “最多读取一次”不要求缓存全部来源字节：只保留已处理身份、紧凑事实及有界共享输入。重复的精确来源直接复用全部已投影窗口事实，不再次读取或保留其重账本。
- 该承诺限于单次调用并对来源预去重；若共享项不能在预算内保留，应明确拒绝或由调用方拆批，不通过淘汰重读后仍宣称只读取一次。实际读取次数据实统计。
- 对缺失文件/损坏来源保留来源失败状态，并按该候选相关窗口表达不足；进程中断/取消时返回或保存已完成边界，不伪造未完成事实。不新增自动重试或历史manifest恢复协议。

首版明确采用单进程流式读取和NumPy数值处理，避免原账跨进程传输及共享基准重复解析。这是本项设计选择，不是并行失败后的静默降级；不接受未实现的多worker配置。若聚焦规模测量显示不能满足预算，再提出有界并行需求，不先复用策略回放进程池。

预算先限定候选-唯一窗口事实数和可读取来源字节；输出观测点及频率子窗工作量。字节预算不冒充Python驻留内存上限，内存另外报告实测峰值。超预算在计算前明确拒绝，不裁剪候选或窗口。

性能报告明确内存测量口径；进程驻留内存RSS与Python分配峰值分别命名，不将后者当作包含全部NumPy/原生分配的总峰值。

## 7. 复杂度与预算示例

设M为候选数、K为窗口对数、U≤2K为唯一窗口数、B为全部候选原始观察点数、C为闭合周期数、W_b为每窗口应扫描的观察点数、W_d为窗口交易日数。

| 工作 | 复杂度/成本 |
| --- | --- |
| 读取/解码/日索引及退出计数 | 按唯一实际来源字节；数值整理O(B+C) |
| 窗口收益与年化 | O(MU) |
| 窗口回撤 | O(MU W_b)，共享基准另按唯一窗口一次计算 |
| 频率子窗与汇总 | 前缀整理O(B+C)，窗口统计约O(MU W_d)，不逐子窗重扫全部交易 |
| 前段及后段目标排序 | O(K M log M)，不建立全候选两两比较矩阵 |
| 常驻结果 | O(MU)；原账内存随最大单账户及共享输入规模变化 |

示例仅用于工程基准，不是S018实验设计：M=800、K=8、选择504交易日、观察252交易日，最多12800份候选窗口事实；日线约483.84万次窗口权益点访问，M30若平均13柱约6290万次。实际计算按市场真实柱数和窗口重用情况统计，不假设A股也有13柱。

不在评审时承诺未测量的秒数。实施验收使用.tmp合成数据测量：读取、解码、投影、选择、序列化与发布分别计时；记录来源字节、读取/解码次数、内存峰值和相同工作量冷/热条件。发布成本单列，不能用纯数值耗时冒充端到端性能。

## 8. 证据和兼容

新增强类型证据包使用独立类型/版本：计划、规则、紧凑窗口事实、分析结果、来源清单、执行统计及限制。通过现有`MaterialEvidenceWrite`序列化发布，再在`DeliveryContent.evidence`显式引用。

材料引用沿用现有接口，通常没有平台级schema字段；JSON内部的类型/版本由新模型序列化及显式消费时检查。现有INTEGRITY只核对选定材料字节和显式引用，不递归认证JSON内部的来源清单或研究语义。
