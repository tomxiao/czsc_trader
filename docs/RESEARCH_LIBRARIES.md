# 第三方研究库使用说明

本文维护第三方工具在本项目中的使用配置；研究目标、阶段交付和授权见[RSCH Agent](../research/RSCH_AGENT.md)。使用前核对当前安装版本及实际调用签名。以下为项目约定，不表示第三方库或平台会自动应用。

## Optuna：参数搜索

### 适用范围与入口

通过Optuna管理参数提议、评价回填和trial状态。联合参数按联合空间研究，单维扫描用于定位。完整账户评价仍调用[TDR研究工具公共入口](../src/czsc_trader/research_tools/__init__.py)，不以搜索器替代SRT/TXE账户计算。

搜索协调公共入口待CAP-03实现；目前由研究代码显式组织调用。调用前核对已安装Optuna的`create_study`、`storages.InMemoryStorage`、`Study`及所选sampler签名。

### 默认配置

| 项目 | 项目约定 |
| --- | --- |
| 存储 | `InMemoryStorage` |
| 并发预算 | `max(1, (os.cpu_count() or 1) // 2)`，本机逻辑核数50%，至少1个 |
| Study所有权 | 主进程持有唯一Study |
| CPU密集评价 | 使用进程执行；Windows采用`spawn` |
| 内部线程 | 每个计算进程的BLAS/OpenMP等内部线程默认1 |
| 小规模网格 | `GridSampler`配合`study.optimize`，按实际版本验证耗尽行为 |
| 锚点 | 使用`enqueue_trial`，按所选sampler验证行为 |

- 运行记录必须包含实际生效配置。
- CPU预算不得表述为CPU利用率保证。
- 内存Study不得替代持久证据。
- 子进程不得各自维护分叉Study。
- 多进程执行前必须验证公共评价支持进程及工作目录隔离。
- 不得把某种sampler的调度方式泛化为全部sampler合同。

### 最小验证与留证

| 检查 | 验证范围 |
| --- | --- |
| 合成运行 | 预算停止、网格耗尽、重复提议、状态导出及序列化 |
| 逐trial记录 | 参数、指标、状态、账户、失败及身份 |
| 复现信息 | 采样、种子、调度、串行／并行复现范围 |
| 接续 | 后继运行引用原记录，不修改已封存原件 |

- 默认配置不适用时必须报告证据与调整方案。
- 不得静默更换存储或并发方式。
- 不得擅自加入降级或兜底逻辑。
- 调整需要新增权限时必须先取得授权。

## tsfresh：时序特征提取

- 适用的时序特征普查应实际使用该库。
- 提取记录必须包含特征集合、遗漏及筛选历史。
- 默认最多使用约半数本机逻辑CPU。
- 统计筛选结果必须进入组件职责评审。
- 统计筛选不得自动授予组件资格。

## expr_codegen：表达式或代码生成

- 生成任务必须声明研究用途。
- 生成结果必须与研究定义逐值核验。
- 生成过程不得自动扩大组件职责。

## pandas、NumPy及统计库：计算

- 调用前必须核对版本。
- 最小验证必须覆盖缺失值、索引、类型及数组可写性。
- 测试必须覆盖实际统计路径。

## 加速或其他第三方评价库

- 使用前必须声明适用交易语义。
- 用于正式比较前必须核验与SRT/TXE的等价范围。
- 未经核验的结果不得替代完整账户证据。

## 依赖边界与能力状态

- 第三方研究库不得自动纳入冻结运行时依赖。
- 安装、升级及跨角色修改必须另行取得授权。

本文承接既有项目用法。统一搜索协调仍待CAP-03实现，完整版本矩阵、可执行示例和能力查询仍待CAP-08补齐；不构成新增平台接口或已完成运行验证的声明。
