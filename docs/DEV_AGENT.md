# 平台开发者工作指南（DEV）

DEV负责将已确认需求实现为准确、高效、易维护的平台能力。本指南规定工程原则与职责边界，具体API、文件布局和操作步骤由所属模块说明维护。
现有实现与测试用于理解当前行为；需求调整时同步修订相关契约，不能以历史行为代替需求判断。

## 1. 可靠性工程原则

- **强类型契约。** 接口具有明确业务语义，以强类型表达输入、输出、约束和状态，在调用边界尽早拒绝非法输入。
- **杜绝假成功。** 成功、失败、部分成功、取消和未知分别表达；返回结果对应实际完成的工作，不将受理、写入或测试通过等同于业务目标达成。
- **代码质量保障正确性。** DEV对自身接口、计算实现及运行可靠性负责，通过清晰设计、聚焦测试和缺陷修复保障正确性，不默认追加一次独立复算来证明首次计算正确。
- **最小实现。** 优先复用已有能力，保持接口和抽象简洁；围绕已确认需求调整实现与调用方，不为假设风险增加流程、认证门槛或兼容兜底。
- **明确运行语义。** 正确处理可变对象隔离、并发竞争、资源释放和失败传播；需要幂等、事务及恢复能力的操作按实际业务契约设计。
- **验证实际风险。** 聚焦测试覆盖正常输出、输入边界及异常状态；模块测试保障自身计算，跨模块测试覆盖受影响调用链，不以重复生产计算代替测试。
- **说明语义影响。** 修改成交、费用、时间对齐、数据可用性或统计口径时，向责任方说明影响及需复验的范围；工程验证与研究验收分别报告。

生产交易、资金、冻结及发布事务的专门约束由所属模块契约和[PTE运维手册](PTE_OPERATIONS.md)规定，不将这些约束泛化为普通研究工具的默认流程。

## 2. 算法复杂度与执行性能

- **设计时评估复杂度。** 按实际输入规模分析时间和空间复杂度，减少嵌套遍历、重复构造及随历史规模增长的额外工作。
- **先消除重复工作，再增加并发。** 避免相同数据和结果被重复计算、读取、解析、序列化、复制或计算指纹；不为处理少量选定对象而展开全部无关对象。
- **复用共享计算。** 在明确的输入、配置和对象生命周期内复用相同结果及共享数据，保证复用条件、对象隔离和失效行为清晰。
- **统筹执行资源。** 按任务性质选择并行方式，复用公共执行能力，控制总进程、线程、内存和I/O开销，避免嵌套并发及无效数据传输。
- **测量完整调用链。** 使用有代表性的工作量，区分计算、材料处理、I/O和调度成本，以调用次数、分段计时或性能剖析支持归因；差额时间和未知原因明确标注。
- **验收性能与结果。** 性能改造同时验证结果等价性和端到端耗时；比较时固定工作量及计时边界，记录资源、冷热状态和测量次数，不将局部或合成基准提速宣称为全链路收益。

## 3. TDR职责边界与角色协作

**TDR负责提高实验执行效率，确保实验行为可审计，不负责证明实验及其步骤的正确性。**

- TDR按调用者明确提供的输入、规则和资源约束组织计算，返回实际结果及成功、失败或缺失状态；内置检查限于本次工具调用契约成立所需的条件。
- 可审计要求保留足以追踪、解释和复现的输入、代码、规则、结果及其关联。TDR按显式请求保存证据，不以每次重新认证、全面核对或复算作为可审计的前提。
- 来源可信性判断、独立账本审计、结果复算和跨阶段深入核验须由调用者显式发起，不隐含在普通计算、读取或发布操作中；工具不自行增加研究硬门或决定实验资格。
- RSCH负责实验设计、步骤合理性、研究标准、证据解释及最终研究核验；DEV负责工具实现及工程验证。工具计算正确、实验行为可审计、研究结论成立分别判断。

### DEV工作空间

- **全项目可读，可写工作空间排除仓库根目录的`research/`及其全部内容。** 读取研究材料用于需求理解和工程分析，研究修改与正式研究执行由RSCH负责。
- 写入限制覆盖直接编辑以及通过公共API、工具、测试、子进程或子agent等方式间接写入真实`research/`，包括生成证据和更新研究状态。
- 工程测试的夹具、临时研究目录及性能基准产物统一放在`.tmp/`，不得以真实研究目录作为输出位置。
- DEV修改平台接口、实现、平台测试及模块README；涉及`research/`中的调用脚本、协议或报告时，提供具体迁移说明，由RSCH修改并验收。

## 4. 模块边界与依赖关系

项目由TDR主应用和七个独立子包组成。下表约束项目内部的直接业务依赖，不列第三方库、测试夹具及只读取安装文件的环境身份检查。依赖方向表示调用方使用被调用模块的契约或实现。

| 模块 | 业务职责 | 项目内直接依赖与限制 |
| --- | --- | --- |
| TDR：`czsc_trader` | 研究上下文、实验与资源编排、历史账户宿主、评价适配、证据交付、技术检验及冻结／升级事务编排 | 使用DFLS、SRT、EC、SE、SM、SC；技术检验另调用PTE隔离检验能力，不将PTE服务运行作为普通研究评价的前提 |
| DFLS：`dataflows` | 策略依赖的数据资产获取、质量校验、可用时间与来源身份，提供行情、日历及动态事实 | 不依赖其他项目模块；不拥有静态交易规则、策略计算或账户账本 |
| SRT：`strategy_runtime` | 共享数据准备、策略加载和计算、策略提案、观察快照及运行包契约 | 使用DFLS；候选键和发布身份检查局部使用SM。不得依赖EC或调用渠道执行，不负责订单规划和账户推进 |
| EC：`execution_channels` | 静态市场规则、共享订单规划；CN模拟盘、US模拟盘、历史回放盘各自的交易执行与账户处理 | 不依赖其他项目模块；只接收宿主准备并投影的事实、策略意图和账户输入，不查询DFLS、不调用SRT、不负责宿主调度 |
| SE：`strategy_evaluator` | 指标、自检、比较、统计与独立账本审计的确定性计算 | 不依赖其他项目模块；消费显式输入，不取行情、不加载策略、不推进账户、不决定研究资格 |
| SM：`strategy_manager` | 研究身份、候选登记、发布与资格记录、生命周期及存储事务 | 不依赖其他项目模块；不计算策略、执行交易或评价收益 |
| SC：`strategy_chart` | 回测和前瞻共用的图表资源与展示契约 | 不依赖其他项目模块；消费宿主投影的观察和执行事实，不重新计算策略、交易规则或历史解释 |
| PTE：`paper_trading_engine` | 模拟盘调度、策略与发布绑定、计算编排、Web控制与监控、审计展示及隔离技术检验 | 使用DFLS、SRT、EC、SM、SC；不依赖TDR或SE。渠道订单、成交、账本与对账实现归EC，PTE组织调用及运维流程 |

### 共用链路与渠道差异

TDR与PTE共用SRT的数据准备和策略计算实现，以及EC的市场规则解析与订单规划实现。宿主按各自任务组织调用：DFLS提供输入，SRT产生策略提案和观察，宿主将提案与执行事实显式投影到EC契约，EC规划订单并通过所选渠道推进执行和账户，确认后的账户快照再提供给下一次策略计算。历史评价由TDR把账户事实交给SE，回测和前瞻展示分别由宿主投影给SC。

策略所依赖的数据资产统一从DFLS取得；静态交易单位、价格精度、可卖与结算规则由EC内部`market_rules`维护。日历、停牌及逐日价格边界等动态数据与静态规则在宿主调用EC时组合，不能把日期事实伪装成静态配置，也不能让EC回调数据源。在线动态可交易性另由渠道按实际执行能力核验，不能伪造历史覆盖事实。

交易执行和账户处理按渠道实现。CN与US模拟盘可共用富途适配和账本基础设施，但市场、币种、时段、账户及资金必须明确隔离；渠道现金、持仓和成交以富途确认为准，交易资金核算正确后的现金差额按既定规则归平账账户，不编造收入来源。SRT及策略只消费DFLS后复权行情，输出目标仓位及解释；报价、数量、资金预算和执行锁由EC处理。DFLS明确返回后复权获取方法（供应商直供或DFLS计算），与供应商身份分开记录。

EC在资金、交易规则和渠道约束内尽力执行合法目标仓位，不保证目标完全实现。受理、订单提交与确认成交分别表达；资金不足、数量取整、未触价、拒单或部分成交返回实际进度、约束原因及账户效果，不能将合法目标暂时不可达当作整个账户的技术失败。不能执行的委托明确受阻，账户仍继续估值、结算及后续决策；非法输入、账户不一致、损坏数据等无法可靠继续的问题仍报错阻断。策略保留目标及金融条件，EC不得修改策略目标以促成成交。

历史盘使用后复权价格报价、成交、记账和估值，数量为整数模拟单位；保留既定步长、价位、费用及结算规则，不处理拆股或派息事件。模拟盘独立读取未复权执行参考价；未知数量变化由EC按已确认渠道事实对账，不推断原因。不得用历史模拟账本替代在线渠道事实，相同策略和订单规则不代表三个渠道的成交与资金事实相同。

### 契约归属与变更约束

- 契约由所属业务模块拥有：数据契约归DFLS，策略计算与观察契约归SRT，执行及账户契约归EC，评价契约归SE，身份与发布契约归SM，图表契约归SC。不得增设没有业务领域语义的公共契约子包来绕过边界。
- 跨域转换由TDR或PTE宿主显式完成，保留身份、时间、数量、资金和状态语义；同名类型不能直接视为同一合同。投影不得重新计算策略，也不得在宿主复制EC的订单数量、价格、费用和账户算法。
- 共享输入准备、策略计算、规则及订单规划只维护一条实现链路；市场差异以明确的市场合同和规则表达，渠道差异放在EC的执行与账户实现。新增依赖同时检查实际导入和安装声明，按普通运行、发布加载、技术检验区分用途，禁止通过动态导入或回调制造反向业务依赖。
- 独立MRS、TXE、FSC、STC已退役，不恢复旧包、转发接口或旧目录／模板调用链。旧研究证据与发布身份保留原件；重跑旧实验须由RSCH迁移调用，仍承担既有账户升级职责的显式数据库迁移不视为废弃接口。
