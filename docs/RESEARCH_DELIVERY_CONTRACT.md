# 研究交付与候选身份契约占位

本文承接CAP-01、CAP-06、CAP-07的工程契约需求，不提供可调用接口。TDR统一阶段产物抽象基类、组装API及候选登记能力尚待实现；正式名称、字段和公共导出路径须在实现验证后填写。研究流程与权限以[RSCH Agent](../research/RSCH_AGENT.md)为准。

## 阶段产物（CAP-01／待实现）

| 产物 | 契约内容 |
| --- | --- |
| 机器产物 | 阶段与版本、研究对象、输入依赖、代码与数据身份、结构化结果、证据索引、状态、未完成范围及复算入口 |
| 人工报告 | 目标、结论、关键证据、研究解释、最强反证、取舍、适用边界及下一动作 |
| 结构定义 | 字段类型、单位、空值语义、结构版本 |
| 引用 | 相对路径及内容哈希；允许引用既有不可变证据 |
| 复算环境 | 依赖、数据权限、随机种子、调度影响和允许误差 |

| 校验对象 | 契约要求 |
| --- | --- |
| 双产物一致性 | 报告中的数值、身份、状态和覆盖与机器产物一致 |
| 解释类型 | 机器事实、金融假设、统计证据及研究判断分别标识 |
| 来源 | 人工解释关联证据引用 |
| 缺失值 | 缺失不得填零 |
| 不适用项 | 必须附原因 |
| 运行状态 | 缺失、部分成功和外部结果未知按实际状态记录 |
| 自包含 | 交付可脱离聊天历史独立解释 |
| 确定性 | 相同输入的确定性计算结果一致 |
| 依赖闭包 | 不依赖未声明临时缓存 |
| 决策记录 | 研究判断、技术检验及用户决定分别记录 |

当前由研究代码生成阶段结构化文件、manifest、schemas及验证结果。平台校验只覆盖交付完备性、一致性和可追溯性；研究员负责方法适用性、证据解释及结论质量。

## 候选身份（CAP-01、CAP-07／待增强）

现有`StrategyCandidate`为运行时输入，代码入口见[SRT公共导出](../packages/strategy_runtime/src/strategy_runtime/__init__.py)。下表中的统一持久化、指纹及身份治理要求为待实现契约，不能由现有类名推断已经具备。

| 对象或事件 | 身份规则 |
| --- | --- |
| 候选含义 | 一套确定的实现、有效参数及固定交易规则；候选身份不表示用户批准 |
| ID范围 | 族内唯一 |
| ID回收 | 不允许回收复用 |
| 内容绑定 | 源码、固定标的及输入绑定、完整有效参数、固定执行规则、契约版本 |
| 实现、参数或固定规则改变 | 创建新候选身份 |
| 窗口、快照、初始资金或费用压力改变 | 创建新评价身份 |
| 阶段三转入阶段四、五 | 保留候选身份 |
| 增加证据、建议或用户决定 | 保留候选身份 |
| 相同行为 | 保留各候选身份，不以行为去重替换候选身份 |
| 标识分类 | 候选ID、评价ID和交易行为ID分别记录 |

## 扰动与冻结关联（CAP-06、CAP-07／待增强）

| 关联 | 契约要求 |
| --- | --- |
| 扰动执行 | 每次评价关联实际执行的候选身份 |
| 扰动派生 | 每次扰动评价记录中心候选关系 |
| 自检归属 | 扰动证据汇总到中心候选 |
| 排序集合 | 扰动配置不自动加入正式候选排序集合 |
| 冻结版本 | `StrategyVersion`关联来源候选ID及内容指纹；现有类型见[SM公共导出](../packages/strategy_manager/src/strategy_manager/__init__.py) |
| 文件闭包 | 源码、依赖及证据以受管文件和哈希引用保留，不另建独立候选包对象 |
| 历史记录 | 历史配置ID、候选包及审批记录保持原样 |
| 迁移 | 保留新旧身份追溯关系，不回写封存实验 |

当前派生关系由研究侧结构化台账记录。统一组装、登记、检验与冻结公共入口仍为占位；能力状态及不可执行时的处理见RSCH附录C。
