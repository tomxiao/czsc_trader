# 交易执行引擎（Trading Execution Engine，TXE）

本文面向策略研究员（RSCH）和平台开发者（DEV）。平台实现与测试入口见
[DEV Agent](../../docs/DEV_AGENT.md)。

TXE 是统一成交执行器，位于 DFLS 同一基础能力层。它接收SRT决策及执行计划，生成可审计的
订单、成交、费用、现金、持仓和净值事实，供研究复算及候选／版本回测共同使用。

`trading_execution_engine.equity.EquityHistoricalExecutor` 增加 US 的显式 BAR_RANGE 研究账户，
复用 `resolve_fill`，支持下一段订单、同日往返、公司行动与交收；原 A 股执行不变。
支持范围、时间精度及拒绝条件见[TDR美股研究接口](../../src/czsc_trader/README.md#us-equity-research)。

## 能力边界

TXE 负责：

- 按 SRT 已确定的订单类型、参考价和委托价执行市价单或限价单；
- 对交易者不利的滑点处理；
- 费用、现金、持仓和净值的确定性记账；
- 对非法价格、数量、费率、滑点和目标仓位明确失败。

TXE 不负责：

- 生成策略信号或目标仓位；
- 获取、发布或修补行情数据；
- 搜索参数或评价策略优劣；
- 管理策略版本、PTE账户或券商订单状态。

PTE仍以渠道成交回报作为模拟账户事实来源。TXE用于研究与回测的统一执行口径，
不能替代Futu订单与成交对账。

## 使用入口与结果

RSCH正式比较策略时，通过TDR的`context.evaluation.evaluate(EvaluationRequest)`或
`run_backtest(context, strategy, request)`取得完整账户事实。由SRT生成逐日计划、TXE执行。
需要自行组织合成或专门回放场景时，可
直接使用TXE公共接口：

- `HistoricalExecutor`：实现SRT的`WindowExecutor`协议，向SRT提供逐日账户快照，接收
  `ExecutionPlan`并管理历史订单、成交、费用、账户状态和完整账本；研究参数搜索、候选/冻结
  策略回测、TDR复核共用这条执行链路；
- `resolve_fill(...)`：根据订单与历史行情判断单笔委托是否成交；
- `execute_target_positions(...)`：供受控数值场景使用的仓位序列辅助接口，按交易日开盘生成订单、
  费用和账户日状态。

后两者是数值能力接口；正式策略回放由 `StrategyInstance.run_window(...)` 驱动
`HistoricalExecutor`，不能用简化仓位收益替代完整执行证据。SRT决定委托类型、参考价、委托价
和生效时点，TXE根据历史行情完成触发、成交、滑点和记账。TDR指定评价窗口、初始资金和
执行数据；回测调用方还必须显式提供与策略执行合同一致的`lot_size`。TDR负责审计、报告与图表。

结果应同时核对订单、成交、费用、现金、持仓和逐日净值；只看信号收益或最终净值不足以判断
执行可行性。正式普通目标仓位回放采用`DAILY_RANGE_V3`：按日开盘及日价格区间判断市价/限价成交，
限价触价可成交；非开盘成交可能仅有交易日精度。该模型不以成交量限制数量，不模拟排队或部分流动性成交。
这属于研究成交简化，PTE模拟账户仍以Futu成交回报为准。

执行器接纳行情时保留独立数值副本，附加在`DataFrame.attrs`中的原始证据由调用方持有，
不随数值副本深度复制。最近收盘价、每日分钟范围及估值来源通过有序时间索引定位；
没有订单的交易日不构造分钟切片。所有复用局限于当前账户内存，不增加磁盘缓存或公共接口，
输入认证、成交判断及账本字段保持不变。

单独调用`resolve_fill`且未提供`daily_quote`时，分钟触价路径默认采用严格穿越；
`inclusive_touch=True`可显式启用触价成交。该辅助路径不代表正式日范围回放已消费分钟数据。

阶段四由TDR将受管TXE事实转换为SE的`AssessmentEvidence`，保留实际成交、费用、周期和
账户轨迹；阶段五技术检验还会重放拟冻结版本并进行独立账本审计与经济等价比较。
调用方不改写原始订单或成交ID来制造一致性；比较时可在副本中按引用关系归一化运行身份，
金额、数量、时点和状态仍按原事实核对。

同版本发布包升级需要哪些等价性验证及如何解释结果，由RSCH负责；TXE提供可复算的执行事实，
TDR升级事务只认证身份、留存材料和提交发布。比较升级前后行为时应固定输入、窗口、初始账户与
执行口径，核对决策、订单、成交、账户和交易账本；声明的展示字段与运行身份须与经济事实分开比较。
历史回放一致说明所检验窗口内的行为一致，不等于PTE渠道成交保证或新发布身份已经获准运行。

TXE不生成信号解释或渲染图表。SRT物化观察快照，TDR将快照与TXE账本投影到
[共享策略图表](../strategy_chart/README.md)；展示不可用不会被解释为零信号、零成交或零持仓。

## 整手数量与完成状态

`execute_target_positions`的开盘价和收盘价、`resolve_fill`的开盘价及传入触价必须为正且有限；
`slippage_bp`须有限并满足`0 <= slippage_bp < 10000`。非法输入或计算后无效成交价明确失败。

`execute_target_positions(..., lot_size=100)`要求`lot_size`为正整数，拒绝`bool`、浮点数、
字符串及非正数。通用辅助接口的`lot_size=None`表示允许小数数量；TDR回测及基准始终显式传入
整手单位，BuyHold与MA5/MA20共享这一数量口径。资金不足一手时保留现金，不生成零数量订单。

`HistoricalExecutor`向SRT返回`ExecutionOutcome`，状态使用
`ExecutionOutcomeStatus.SETTLED`。它表示该计划执行处理完成并已记账，可以包含未成交委托；
订单是否成交、原因及数量仍以明细为准。自定义`WindowExecutor`同样必须返回强类型结果及
匹配的计划身份，失败使用`FAILED`；SRT遇到失败状态会停止窗口执行。

执行器必须在`ExecutionCapabilities`中如实声明`OrderType`枚举元组和检查点能力。
SRT在首次账户快照前检查策略要求，并逐计划复核，避免运行到不支持的订单后才发现能力不足。

### 信号分配与交易周期预算

`capital.mode=signal_cash_fraction`、`target_scope=entry_cycle`使用SRT的类型化
`CycleTarget`和`EntryCycleState`。策略可以逐周期选择投入比例；TXE接纳计划时才锁定周期身份、
现金预算和目标份额，调用SRT生成或预览计划不改变账户。重复执行同一计划返回既有结果，
不重复分配或重复扣费；计划携带的周期前状态必须与当前账户完全一致。

实际买入成交额及买入费用累计消耗预算；卖出收入不会增加本周期可用预算。未成交保留原周期，
后续补买同时受剩余份额、剩余预算及可用现金限制。已持仓期间信号比例或价格变化不触发每日再平衡。
退出周期只有在持仓归零且本次历史订单全部终结后释放；历史未成交订单属于当日终结状态，
后续交易日通过新的计划重试。历史成交模型仍不模拟单笔订单的流动性部分成交。

新模式在决策账本记录信号比例、锁定比例、周期身份、预算、目标数量、累计买入成本及计划状态；
日账户账本记录收盘后的周期身份、阶段、预算和累计买入成本。订单、成交和交易周期沿用同一周期身份。
这些字段仅对新模式增加，现有固定投入和每日权益目标模式的账户计算保持原语义。
账户始终从初始现金与空周期启动，不从历史持仓数量推测原分配或预算。

## 研究账户评价口径

`HistoricalExecutor`按整个交易周期累计买入成本、退出收入及费用；分日退出后再次加仓仍归入
同一未结束周期，清仓时计算完整周期收益率和按成交数量加权的买入、退出均价。

`HistoricalExecutor`保留SRT多档位目标比例，不将小数目标截成0。部分减仓、补买和再加仓均按实际
成交更新现金、份额和费用，只有实际清仓才闭合周期。极小正比例因整手取整导致实际清仓时也结束周期，
后续买入建立新周期；未成交订单不改变持仓。目标数量计算见[SRT执行计划](../strategy_runtime/README.md#执行计划)。
交易记账支持多次成交不等于账户归因诊断支持该类账户，后者仍按[TDR账户诊断](../../src/czsc_trader/README.md)的范围返回状态。

先核对[TXE公共导出](src/trading_execution_engine/__init__.py)及[SRT公共导出](../strategy_runtime/src/strategy_runtime/__init__.py)。下表为研究评价合同要求，不代表现有执行器自动覆盖全部场景；能力不满足合同时须报告限制并请求用户决定。

| 项目 | 合同要求 |
| --- | --- |
| 决策与成交时间 | T日收盘信息只能驱动之后可执行的订单 |
| 账户价格 | 真实报单、数量、费用及账户估值采用真实市场价格口径 |
| 复权换算 | 不得未经换算将后复权价格用于真实持仓估值 |
| 权益事件 | 账户核算包含分红、拆分等权益事件 |
| 独立窗口 | 按合同重置资金与持仓 |
| 原账户切片 | 单独标识，不作为独立窗口回测 |
| 比较口径 | 基准和策略分别声明日期、价格、成本、资金、订单及整手规则 |
| 口径差异 | 显式披露，不擅自替换研究基准 |
| 账本 | 下单、成交、持仓和收益分别记录 |

研究流程以[RSCH Agent](../../research/RSCH_AGENT.md)为准；TDR公共调用示例见[TDR说明](../../src/czsc_trader/README.md)。

美股正式策略的 `EquityPlan.explanation` 随决策事实保存。历史账户快照提供当前开仓周期进入时点及成本，
标记区间成交反馈；只提供已经生效的账户事实，计划不等于成交。旧研究函数式策略仍使用原执行规则。
正式美股策略通过 `snapshot_at(observed_through, decision_at)` 在决策前应用已生效的公司行动与到账事件；
跨拆股边界的前一根原始收盘价仅在下单参考价中转换到当前股数单位，分析历史仍明确为 RAW。
该处理与旧函数式研究路径分别标识，不改写历史证据。

### 美股行情缺口与陈旧估值

显式启用 DFLS `UsEquityBarPolicy` 时，`MISSING`、`ZERO_VOLUME` 及与已知不可交易区间重叠的行情柱
禁止成交。有下单尝试时分别记录 `EXPIRED` 和 `MISSING_BAR`、`ZERO_VOLUME`、`KNOWN_INTERRUPTION`；
已知中断覆盖行情柱的一部分时，本模型保守地阻止整柱成交，不推定柱内具体成交时间。
缺口本身不证明历史停牌，完整取数也不保证供应商无漏数。

缺失或零量区间仍保留账户点，沿用最近有效收盘价估值，`valuation_stale=True`；
`valuation_price_at` 保留该有效价格的原时间。首次执行区间缺失时必须已有有效预热参考价。
公司行动、现金到账及持仓核算继续发生；拆股同步调整沿用价格的股数单位，不能造成虚假净值跳变。
行情恢复后更新估值，正常行情上的已知执行阻断不妨碍收盘估值。账户同时记录 `bar_status` 和
`execution_blocked`，TDR 汇总日期、区间和受影响订单，SE 独立核验。

沿用价格只用于账户估值，不补入策略信号历史。陈旧估值可能低估缺口期间的价格波动和回撤，
属于需披露的研究限制。默认严格数据路径及 A 股撮合语义保持不变。
